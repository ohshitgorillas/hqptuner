## What is wrong

A change confined to `tests/` pays the full price of a change that touches the implementation. Today a test that violates `docs/testing.md` and has to go travels `kind: excision` (`docs/testing.md:75-85`), and everything around it is still the implementation chain: a stage 1 plan through the gauntlet-prosecutor (`CLAUDE.md:18`), a red run whose verdict the writer certifies (`CLAUDE.md:30`, `.claude/commands/tests.md:105-123`), and a post-merge reviewer round over the landed diff (`scripts/pair.sh:498-529`, `.claude/commands/tests.md:144`). All three exist to police an implementation phase. A deletion has none: there is no code to be wrong, and the citations such a block makes are into `tests/`, which the reviewer may read — the gauntlet-arbiter's read list ends "and every file under `tests/`" (`.claude/agents/gauntlet-arbiter.md:62`).

Two gaps follow. There is no way to state "this test goes, and this behavior takes its place" in one block — `docs/testing.md:75-85` gives excision lines `rule:` and `assertion:` and nothing that names a replacement, and the file has no `kind: repair` anywhere. And the one check that would catch a softened deletion mechanically does not exist here: `scripts/` holds no `excision-diff.py`, and `do_merge` (`scripts/pair.sh:533-649`) reads no `kind:` at all, so a landed tests-only diff is compared against the red commit (`:512`, `:516-528`) rather than against the block that approved it.

## What changes

**1. `kind: repair` in `docs/testing.md`.** A new section beside "Excision blocks" (`:75-85`), in this file's own prose, carrying the grammar upstream states at `~/dev/gauntlet/docs/testing.md:95-112`: one line carries both halves, `excise tests/<file>::<test>` with `rule:`, `assertion:`, then `replace:` naming the behavior as a caller sees it, `as:` naming the test the replacement must land as, and `kills:`. No `bite:`, because the replacement pins behavior HEAD already has, which `docs/testing.md:31` (rule 8) exempts in the same clause that exempts characterization: "Tests with no pre-change state to fail against — characterization of existing behavior, tests accompanying a pure refactor — are exempt". No whole-file targets, since a replacement cannot land in a file the excision half deleted. The four-line cap counts `replace:` lines only. `as:` may equal the target, since a coupled test name often states the behavior correctly and only the assertion is wrong.

This grammar needs no change to the spec gate. `scripts/gates/check_spec_draft.py:67` decides a line is an excision by whether its head starts `excise`, so a repair line is read as one: `_excision_flags` (`:118-119`) then requires `rule:` and `assertion:`, which every repair line carries, and `_committed_flags` (`:121-124`) requires the first clause to be `rule:`, which it is. `Makefile:22` runs that gate over every committed `tests/specs/*.txt`, so a landed repair block is gated on the path it already takes.

**2. New `scripts/excision-diff.py`**, ported from `~/dev/gauntlet/scripts/excision-diff.py` (223 lines), including its `self_test()` and the `--self-test` entry point, the same shape `.claude/hooks/plans-lane.py:108` carries. It reads the approved block, takes `--spec`, `--base` and `--head`, prints one line per target — `OK`, `UNSATISFIED` (the target is still there, assertion and all), `MISSING` (the replacement the `as:` field promised never landed), `UNNAMED` (a file under `tests/` changed that no line names) — and exits 0 only when every printed line starts `OK `. A target is satisfied on either fact: the test name is gone from the file, or the name is present and the quoted `assertion:` text is no longer in that test's own body, body rather than file because the same assertion text can sit in a sibling parametrize case.

The reading at the boundary the `UNNAMED` verdict draws: `changed_files` diffs `--base`..`--head` over `tests/` entire, so a replacement that also needs a shared support file — `tests/conftest.py`, a `tests/fake_*.py`, anything under `tests/support/` — produces a changed path no line names, and the merge dies with `UNNAMED <path>` and no escape. That is deliberate and is stated in the lane text: the fast path covers a change confined to the test files its own block names, and a repair that needs a new or edited fixture is outside the lane and takes the ordinary chain, plan gate and red run included. The alternative — treating the support paths as named by default — would let a fixture change ride in under a block that never mentioned it, which is the softening this check exists to catch.

Two divergences from the upstream file, both forced by this tree. The reviewer separator is `--- spec-reviewer READY ---` here (`.claude/agents/gauntlet-arbiter.md:58`), not upstream's `--- reviewer ---`, so the parse splits on the former. And this tree's excision grammar admits a node target, `tests/js/<file>::"<test title>"` (`docs/testing.md:85`), which has no `def` for upstream's `test_body` to bound: for such a target the check reads the whole file rather than a test body, which is weaker in exactly the sibling-assertion case upstream's comment names. That weakening is stated in the script's docstring rather than hidden.

## Where the whole-file removal goes

Upstream drops the red run for both tests-only kinds, and so does this plan. The one thing in this tree that a red run does for such a block is remove a whole-file excision target: `do_red` calls `excise_whole_files` (`scripts/pair.sh:444-446`, the function at `:265-283`) before the lane check, because `.claude/hooks/tests-lane.py` denies every agent the shell that would remove it, and `docs/testing.md:85` states that division. So the call moves rather than staying: out of `do_red` and into `do_merge`, ahead of the spec-tree lane check at `:543` and the commit at `:551`, for the same reason the comment at `:442-443` gives at its old site — the removal is work the spec tree is doing, so the lane check has to see it and rule on it. It moves, it is not copied: `do_red` loses the branch, so there is one place that removes a whole file and no pair can do it twice. With that moved, neither kind needs `pair.sh red` at all: the spec tree's tests are committed by `do_merge` step 2 (`:550-552`), and the block's contract is checked against that commit by `scripts/excision-diff.py`. The certification round goes with it, since a bite proof is a claim about an implementation and neither kind has one.

## What it costs

No rebuild, no container, no playback interruption: nothing under `hqptuner/`, static assets or dependencies changes, which is what `CLAUDE.md:40` keys the rebuild on. The new file is Python under `scripts/`, so it is inside `ruff` and `black` (`Makefile:6-7`), strict `mypy` (`pyproject.toml:160`), and the file-length and nesting gates (`Makefile:12-13`), and outside the coverage floor, whose source is `hqptuner` alone (`pyproject.toml:63`). Six markdown files are touched — `docs/testing.md`, `.claude/commands/tests.md`, `.claude/agents/gauntlet-testsmith.md`, `.claude/agents/gauntlet-arbiter.md`, `CLAUDE.md` and `.claude/skills/gauntlet/SKILL.md` — so `md-by-tool.py`, `md-softwrap.py` and `check_md_trivia.py` apply to all six, and `.claude/hooks/tests-lane.py` takes a docstring edit inside a Python file already covered by the lint gates named above.

The risk is one-directional and worth naming: this lane removes a gate from a class of change. What holds it is that the class is decided by the committed `kind:` line, which the gauntlet-arbiter wrote and `pair.sh` reads from git, and that the lane check already refuses a spec tree that writes outside `tests/` (`:543`, `lane_check` at `:189-199`). A block that claimed `kind: repair` while its tree touched `hqptuner/` would be stopped there, before the merge check runs at all. Six of the nine touched files are chain definitions, so what this plan changes is mostly what the chain's own agents are told, and a sentence left stale in one of them is a reviewer or a writer acting on a rule that no longer holds — which is why the eleven passages above are disposed of by name rather than left to be found.
