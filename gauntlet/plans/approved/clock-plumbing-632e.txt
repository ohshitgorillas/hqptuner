## What is wrong

Two sites under `tests/` hold a real clock, and both violate `docs/testing.md:19` rule 7.

**`tests/support/fake_metering.py:97`**, `await asyncio.sleep(self._interval)`, inside `_pump`'s repeat branch (`:91-105`). The offline suite does not spend it: every construction site takes the `interval: float = 0.0` default at `:53`, so the call is already a bare yield. The grounding round confirmed that no call site anywhere in the tree passes `interval` to any of the three surfaces that take one. The 5 ms that does get spent lives on the two threaded spawners' own defaults — `spawn_threaded` at `:154-166` and `spawn_threaded_stream` at `:169-178`, both `interval: float = 0.005` — and it is spent by exactly one caller, `tests/e2e/support/stack.py:219`.

That is the shape of the defect: a hazard rather than a live wait. A constant in a shared fake, one keyword away from being spent by any offline test, sitting in the tree the gate refuses. It is also mis-filed: the two threaded spawners exist for the e2e stack and have no other consumer, but they live in `tests/support/`.

**`tests/api/test_connection_lane.py:55`**, `"request_timeout": 0.05` in the `app_factory` fixture (`:36-64`). This one is live, and `idle-gate-ba28`'s measurement clocked it at 48-50 ms. It survived the `idle-excise-ba28` excision: that block removed the test which spent the deadline, and the fixture default that creates it stayed behind.

The file holds two test functions, both parametrized, so **six builds**: `test_a_save_reports_the_lane_its_own_config_attempt_reached` at `:76` with four cases (`:67-74`), and `test_an_unset_record_reads_as_ask_every_time_and_a_stored_choice_reads_back` at `:96` with two (`:95`).

**What spends those 50 ms is not the control lane, and this is the load-bearing fact of the plan.** The obvious repair — delete the line and let `request_timeout` fall back to its `5.0` default at `hqptuner/config.py:83` — would make the suite dramatically worse, not better. `TestClient(create_app(cfg))` runs the app's lifespan, whose first statement (`hqptuner/api/lifespan.py:61`) is `_adopt_alias`. That probes the container host alias (`:29-31`):

    if not host_is_unchosen(connections.read()):
        return
    answered = await probe(cfg.container_host_alias, cfg.hqp_control_port, cfg.request_timeout)

The guard is `host_is_unchosen`, `hqptuner/core/connection.py:116-122`, true when no record file exists and `HQPTUNER_HQP_HOST` is unset. `app_factory` points `connection_file` at an empty `tmp_path`, and the session-autouse scrub at `tests/conftest.py:60-77` deletes every `HQPTUNER_*` name except `HQPTUNER_CHROMIUM`. There is no truthiness test on the alias and no early return in `probe` (`hqptuner/engine/discovery.py:115-124`), and the alias resolves to its default, `"host.docker.internal"` (`hqptuner/config.py:97`), which nothing in the test environment answers, so the probe runs to the deadline `asyncio.wait_for` holds at `hqptuner/engine/control.py:147`.

**Both edges of that guard, since only one of them probes.** Five of the six builds probe. The sixth does not: the `(True, True)` case of `:95` writes a `ConnectionRecord` through `ConnectionStore(store_path).write(record)` at `:101-103` before building at `:104`, so `host_is_unchosen` is False and `_adopt_alias` returns at `hqptuner/api/lifespan.py:29-30` without probing. That build spends nothing today and nothing after, so it is neither a cost nor a saving.

The `0.05` is a muzzle on that probe. Removing it uncages a 5.0 s wait on each of the five.

## Which files get touched, and roughly how

**`tests/support/fake_metering.py`.** `MeteringStream.__init__` (`:53`) drops `interval` outright, taking nothing in its place, and `_pump` (`:91-105`) replaces `await asyncio.sleep(self._interval)` at `:97` with a bare `await asyncio.sleep(0)`. The `await writer.drain()` already at `:96` is what paces the loop after that: a write that outruns the consumer blocks there until the socket buffer clears. `spawn_threaded` (`:154-166`) and `spawn_threaded_stream` (`:169-178`) drop their `interval: float = 0.005` defaults with it. After this the file holds no clock at all, and the `repeat=None` queue branch (`:99-103`) is unchanged, since it never slept.

**`spawn_threaded` and `spawn_threaded_stream` do not move, and nothing gains a sleep.** An earlier draft moved them into `tests/e2e/support/` so their 5 ms default would sit inside the gate's path carve-out. That relocated the clock instead of removing it, and it needed a clause on `docs/testing.md:26` to be legal on the prose as well as on the gate. Both are withdrawn. The two spawners keep their home, lose their `interval` parameter with everything else, and `docs/testing.md:91`'s rule that the browser suite drives "the same wire fakes the offline suite uses" holds by construction rather than by argument, since there is now one fake and no second pacing path.

**What paces the e2e stack once the constant is gone.** Backpressure, which is a condition and not a clock. `_pump` already awaits `writer.drain()` at `:96` before its sleep; a pump that writes, drains and yields advances exactly as fast as the consumer takes frames, and the consumer in the browser suite is a real `python -m hqptuner` subprocess reading a socket. `drain()` is backpressure, not a poll: it has no ceiling and no condition it re-checks, and the rate it settles at is not known here. So it is not what `docs/testing.md:26` allows, and this plan does not invoke `:26` at all — an earlier draft leaned on that line twice and was wrong both times. No carve-out is needed, because the sleep is removed rather than relocated: after this change `tests/support/fake_metering.py` holds no non-zero sleep, so nothing this plan touches sits in `tests/e2e/` and `:26` has no surface left to be invoked on. The claim is that narrow on purpose. Six non-zero sleeps under `tests/` survive this change and are not its business: `tests/conftest.py:222`, which belongs to `clock-seam-632e` per the paragraph below, and five inside `tests/e2e/` — `test_abuse_bracket.py:126`, `test_hwapply.py:173`, `test_livepreset_repick.py:166` and `:183`, `support/stack.py:182` — which are exactly the sites the gate's path carve-out exists to spare (`docs/gauntlet/specs/approved/idle-gate-ba28.txt:126`). What this plan removes is the one fixed metering interval, not every clock under `tests/`.

**`tests/e2e/support/stack.py`** is not touched. `:219` calls `spawn_threaded_stream(_repeat_frame())` positionally and passes no interval, so dropping the parameter leaves the call as written; the generator protocol around it (`:224` takes the port, `:244` resumes for teardown) is likewise unchanged.

**`tests/api/test_connection_lane.py`.** The `"request_timeout": 0.05` key at `:55` is replaced by a `container_host_alias` override of `"127.0.0.1"`. The alias probe then attempts that address at `cfg.hqp_control_port`, which the fixture already points at `closed_port` (`:49`) — a port bound and released, so refused at once by the kernel — and `probe` returns `None` through its `except (OSError, ControlError)` at `hqptuner/engine/discovery.py:123-124`, the same `None` an unreachable host gives it today, by the same code path.

**`tests/support/fixtures_daemons.py`** is read but very likely not edited: the construction at `:204` is `MeteringStream(repeat=repeat)` and passes no `interval`, so it is unaffected by the signature change. It is listed because the plan cannot promise that without the writer's hand on it.

## What it costs

**The change:** one parameter dropped from three signatures, one `await` swapped for a bare yield, one internal forward, one fixture key. No file moves, no new file, no doc edit, no production code. No `CHANGELOG.md` entry — nothing here is visible to a user of the application.

**What it buys:** the shared fake stops holding a clock anywhere, in either tree, rather than holding one in a tree the gate does not read. `test_connection_lane.py` stops spending 48-50 ms on each of five builds.

**The risk this design carries and the moved-constant design did not.** Dropping the interval changes the e2e stack's frame rate from 5 ms to whatever the consumer sustains. `await writer.drain()` bounds it — the pump blocks once the socket buffer is full, so the rate is the subprocess's read rate rather than a spin — but that rate is not 200 frames a second and is not known here. Two things follow. A browser test that depends on frames arriving slowly enough to observe could change behaviour, and a consumer that reads fast makes the pump busy where it used to idle, which `~/dev/CLAUDE.md` 3.2 counts on actual footprint rather than intent. Both are measurements against the running e2e stack, so they are the `gauntlet-accountant`'s at stage 2: the sustained frame rate and the pump's CPU, against the same stack today at 5 ms. A rate that saturates a core sends this back to stage 1 for a bounded condition on the stack's own state rather than on drain alone.

**Where `request_timeout` still goes, corrected.** The earlier draft said it "is never reached", and that is wrong. It is reached, one hop from the changed fixture: `TestClient` starts the lifespan, `hqptuner/api/lifespan.py:62` starts `manager.run()`, `hqptuner/core/manager.py:154` calls `loader.connect_and_load`, and `hqptuner/core/loader.py:37` builds `ControlClient(cfg.hqp_host, cfg.hqp_control_port, cfg.request_timeout)`. The fixture's own comment at `:53-54` names that path. Reached is not spent: `hqp_control_port` is `closed_port` (`:49`), the same refused loopback hole the alias probe will now hit, so the deadline is a ceiling the connect never approaches. That rests on the same refusal mechanism as the alias override and folds into the one ASSUMED below rather than standing as a separate claim.

**The risk, named.** The alias override changes what the probe talks to, from an unresolvable name to a refused port. Both answer `None` through `probe`'s own `except (OSError, ControlError)`, so the lifespan sees no difference — but the failure mode moves from a timeout to a refusal, and if any assertion distinguished those, this is where it would show. One case in the file does assert an unreachable-lane outcome: `("nothing_on_the_port", "no_answer")` at `:73`, asserted at `:92`. It is not this path. That verdict is reached over the HTTP lane, which the case points at `closed_port` through `hqp_http_port` at `:88-89`, and its deadline is not `request_timeout`; removing the fixture key cannot move it. Stage 2 pins that all four lane verdicts are unchanged.

**What is ASSUMED, and it is one thing:** that a connect to `127.0.0.1` at a released `closed_port` is refused promptly rather than waited out, on this host. `closed_port` (`tests/conftest.py:394-405`) binds port 0, reads the number and closes, so nothing holds it. That single fact carries both the alias probe and the `loader.py:37` control client. Settling it is a timing measurement, so it is the `gauntlet-accountant`'s at stage 2 rather than a number typed here; the measurement command is `-k`-selected rather than path-selected, since `.claude/hooks/tests-lane.py` denies a shell command naming a `tests/` path.

**Deliberately left out:** `tests/conftest.py:222` and the `ConnectionManager.run()` pacing seam. That is the other plan, `clock-seam-632e`. It touches production code and retires a normative rule, and nothing is gained by landing the two together.
