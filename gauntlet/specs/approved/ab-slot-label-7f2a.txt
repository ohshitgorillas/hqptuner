wire and protocol facts:

- /api/state carries active_chain: which chain the engine has loaded, the configured mode outright in pcm and sdm, and the family of the playing rate in auto (docs/architecture.md:91).
- The two chains carry different enumerations, and a filter value is an enum ID within its own chain's list (docs/protocol.md §4, §6). PCM's 1x filter live form field is filter1x.
- An enumerated name is the engine's to change: a stored ID carries the name it was picked with, and the name the running enumeration gives that ID is what the card shows while the ID is still offered (docs/architecture.md, live snapshots).

applicable fixtures:

- tests/js/support/chainenums.js — the daemon's own two chain enumerations, PCM and SDM, whose enum IDs deliberately differ from their list indices.
- tests/js/support/ — the vendor resolve loader the JS suite runs under, and the DOM and localStorage setup the existing component suites use.
- tests/js/store/liveab.test.js — the existing store suite for this card, showing how engineState/enums/config are driven offline.
