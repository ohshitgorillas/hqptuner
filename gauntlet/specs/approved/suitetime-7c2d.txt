Public entry points (planned, scripts/gates/check_suite_time.py):

    ESCALATE = 5.0   #: seconds over the baseline past which the run needs the owner's accept
    REJECT = 10.0    #: seconds over the baseline at or past which no accept is taken

    def check(report: Path, baseline: Path, *, accept: bool = False) -> int:
        """Refuse a run slower than the last green run by more than ESCALATE seconds.

        Reads the junit report pytest wrote and the baseline file. Exit 0 records the report's time as the new baseline. A red report (failures or errors non-zero) is not judged and not recorded, exit 1. A missing report exits 1. A missing baseline is seeded from the report, exit 0. `accept` records a run in the escalate band as the new baseline; a run at or past REJECT over the baseline is refused with or without it.
        """

    def main(argv: list[str] | None = None) -> int:
        """CLI: optional `--accept`; report and baseline resolved to the main checkout."""

Wire and protocol facts (no daemon involved; the report format is pytest's):
- pytest's `--junitxml` writes `<testsuites name="pytest tests"><testsuite ... errors="N" failures="N" ... time="S.SSS" .../></testsuites>`; `time` is the session's elapsed wall time in seconds (.venv/lib/python3.14/site-packages/_pytest/junitxml.py:653, 664-682).
- Baseline file is JSON `{"seconds": <float>}`.
- Owner rulings: "an increase of more than 5s is cause for escalation to me, 10s increase rejected outright"; baseline is the last green run.

Applicable fixtures: `tmp_path` only. Tests hand-build the report XML and the baseline JSON under `tmp_path` and call `check` with those paths, the pattern of tests/gates/test_coverage_floor.py. Nothing runs pytest or coverage.
