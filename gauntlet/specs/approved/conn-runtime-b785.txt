> Runtime host+credentials only

wire and protocol facts:

- The 8088 configuration interface takes HTTP Digest auth in realm com.signalyst.hqplayer.embedded; read-only use and every live 4321 setting work without credentials, and only persistent writes and preset switching need them (docs/architecture.md section 3).
- An install with no credentials has no 8088 lane, so `ready` never turns true and the page runs dimmed, the same reading a refused credential gets (docs/architecture.md section 3).
- A refused credential arrives as 401 or 403 and is raised as AuthRefused, a subclass of httpx.HTTPStatusError, so every lane already catching httpx.HTTPError catches it unchanged (docs/architecture.md section 3, hqptuner/conf/httpauth.py).
- hqplayerd's management pair is not a secret: the daemon is LAN-only and the stock pair is published in its own documentation (CLAUDE.md, hqplayerd-readme.txt section 1.0).
- The 4321 control lane carries no authentication at all; SessionAuthentication is not used and the daemon rejects self-generated client keys (docs/architecture.md section 3, docs/protocol.md sections 3.5-3.6).
