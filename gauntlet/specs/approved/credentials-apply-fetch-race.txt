wire and protocol facts:
  - The settings archive is `GET /backup/settings.zip` on the 8088 configuration lane; the bare `/backup` route is only the HTML page (docs/protocol.md:68).
  - Every page on 8088 needs authentication. With no `Authorization` header the daemon answers 401 and a digest challenge; a digest built from a wrong password answers 403 with the same 40-byte body. `httpx.DigestAuth` consumes the 401 and re-sends, so 403 is what a caller carrying bad credentials sees, and a client that has already cached the challenge spends one arrival on a refusal rather than two (verified on 6.0.4, tests/support/fake_http.py:69-86).
  - The 4321 control lane carries no authentication, so a daemon refusing the 8088 credentials stays reachable throughout (docs/architecture.md §1).
  - HQPTuner's persistent writes ride `POST /restore`, whose `scope=system` self-restarts the daemon; success is confirmed by a `/backup` readback and never by the POST (docs/protocol.md:88). Neither case in this block reaches a restore.
  - `GET /backup/settings.zip` returns an empty archive after a named `POST /config/profile/load` until the service restarts (docs/protocol.md:95-97). Not reached here; the daemon in both cases is refusing before any profile load.
