## Behaviors

1. A live snapshot name carrying a path separator is refused 422 with code `name_invalid` on every live-snapshot verb, whatever the shape of the name: sweeping the names `a/b` and `a/b/c` across `PUT /api/livepresets/{name}`, `POST /api/livepresets/{name}/apply` and `DELETE /api/livepresets/{name}`, all six answer (422, `name_invalid`).
   kills: declaring the name as one path segment that cannot contain a separator, so a slashed name matches no route, reaches no handler, and is answered by the static-asset mount instead of by the name rule.
   bite: HEAD answers 405 to all six, body `{"detail": "Method Not Allowed"}` with no `code` field: `PUT /api/livepresets/a/b`, `POST /api/livepresets/a/b/apply`, `DELETE /api/livepresets/a/b`, `PUT /api/livepresets/a/b/c`, `POST /api/livepresets/a/b/c/apply`, `DELETE /api/livepresets/a/b/c`, each path reaching the app as written. Measured on `live_api` at its default empty store: `PYTHONPATH=/srv/hqptuner:/srv/hqptuner/tests:/srv/hqptuner/tests/support /srv/hqptuner/.venv/bin/pytest -q -s -p no:cacheprovider -p conftest -p fixtures_clients -p fixtures_daemons <throwaway>`, each request issued as `client.request(method, path, follow_redirects=False)`.
   existing: none. `grep -rn "405" tests/` prints nothing. The name-refusal cases that do exist percent-encode the whole name before sending it (`tests/api/test_livepreset_errors.py:62-68`, `tests/api/test_api_error_codes.py:24`), which is what lets those names reach the rule at all.

2. A save refuses an unusable name before it reads the engine: on an engine whose loaded chain cannot be determined, `PUT /api/livepresets/a/b` is 422 with code `name_invalid`, while `PUT /api/livepresets/Warm` on that same engine is 409 with code `chain_unknown`.
   kills: taking the engine snapshot first and validating the name afterwards, so an unusable name is answered by whatever the engine's state refuses rather than by the name rule.
   bite: HEAD answers 405 with no `code` field to `PUT /api/livepresets/a/b`, and 409 `chain_unknown` to `PUT /api/livepresets/Warm`, on a client built as `chain_api(mode="0", _active_mode="")`. Same command as line 1.
   existing: the 409 half only, at `tests/api/test_livepreset_errors.py::test_saving_with_the_engines_chain_unknown_is_a_conflict`. `grep -rn "chainless_api" tests/` returns eight lines, all in that file (90, 114, 115, 119, 123, 126, 127, 128); every one of them sends the name `Warm`, and none sends a name the rule refuses.

3. Deleting a config preset refuses a name the store's rule rejects instead of answering as a wrong method: `DELETE /api/preset/a/b` and `DELETE /api/preset/` are both 422 with code `name_invalid`.
   kills: declaring the delete route's name as one path segment that can be neither empty nor separator-bearing, so a slashed or empty name is answered by the static-asset mount and never reaches the store rule.
   bite: HEAD answers 405 with no `code` field to both, each path reaching the app as written. Measured on the `http_client` fixture, same command as line 1.
   existing: none for either input. `grep -rn "405" tests/` prints nothing, and `grep -rn "api/preset/" tests/` returns no DELETE of a slashed or empty name; the DELETE cases there are `tests/api/test_api_config_ops.py:117` (`Kept`) and `:121` (`Nope`).

## Wire and protocol facts

No daemon behavior bears on this. The binding reference is the refusal envelope and code table at `docs/architecture.md:64-81`: every refusal is `{"detail": ..., "code": ...}`, `name_invalid` maps to 422, and `detail` is user-facing prose no test asserts (`docs/testing.md` rule 9).

One quirk the tests must survive: httpx normalises dot segments before sending, so a literal `../..` name never reaches the app. The traversal shape is reachable only percent-encoded, and that is already pinned at `tests/api/test_api_error_codes.py:24`.
