wire and protocol facts:

- /api/state carries active_chain: which filter/shaper chain the engine has loaded. It is the configured mode when that mode is pcm or sdm, and in auto it is resolved from the rate the engine reports playing; it is absent when auto has nothing playing (docs/architecture.md:91, "The loaded chain takes filter/shaper edits live (`active_chain`, resolved from `Status.active_rate`)").
- The two chains carry different enumerations, and a filter or shaper value is an enum ID within its own chain's list (docs/protocol.md §4, §6). PCM's three live form fields are filter1x, filter, dither; SDM's are oversampling1x, oversampling, modulator.
- Stored enum IDs are stored with the display name they had, values apply and names only render, because engine-built enumerations shift under a stored record (docs/architecture.md:133).
- A live write goes out as POST /api/config/live with body {"fields": {field: value}} and is readback-verified by the backend; no daemon restart (docs/protocol.md §6, docs/architecture.md:133 on the live lane). This spec adds no line for it: the write path is store/live/write.js writeLive, already pinned by tests/js/store/live.test.js.
