wire and protocol facts

- Saved profile names reach the page over GET /api/matrix (`hqptuner/api/routes/matrix.py`). The picker's list is the union of the profiles the config file carries with the profiles the daemon read at startup, so it has no single engine-supplied sequence to preserve; docs/architecture.md:24's enumeration-ordering authority names five queries (`GetModes`, `GetFilters`, `GetShapers`, `GetRates`, `GetJunkFilters`) and the saved-profile list is none of them. Nothing in this block asserts a row order.
- A profile is a whole matrix context, `<post_process>` included (hqplayerd-readme.txt §1.11.2); loading one is the live 4321 lane and undisturbs playback. Nothing in this change reaches that lane.
- Descriptions are HQPTuner's own store, GET/PUT /api/descriptions, keyed by profile NAME because `<matrix_profile>` carries only `name` (hqplayerd-readme.txt §1.12) and hqplayerd's config has nowhere to hold the text.
- Nothing in the descriptions feature is gated on the descriptions preference `notesVisible` (docs/matrix-spec.md:49): that preference hides prose HQPTuner wrote, and a profile description is prose the user wrote.
- `[Default]` is wire data, not copy: it is the name the daemon's own page carries for the unnamed profile (tests/support/fixtures/matrix-6.0.4.html:42, served by tests/support/fake_http.py:546).
