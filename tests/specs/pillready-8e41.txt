> A bug in the program causes preset changes or engine restarts to incorrectly report Connected before it's actually ready. The sequence goes: 1. Applying 2. Connected 3. Unavailable 4. Connected.
> BOTH LANES MUST BE AVAILABLE BEFORE THE APP REPORTS CONNECTED. The flow should be Applying > Connected. Unavailable is a status reserved for when the engine does not return as expected, not routine applies. This eliminates the 'Attention' status entirely.
> Both lanes must be available, and on a connection established after the write, before the app reports Connected. The control lane (4321) and the HTTP configuration lane (8088) each count.
> Unreachable — a lane did not come back as expected. This includes a refused or absent credential leaving the 8088 lane unavailable.
> The Attention status is deleted. Its only input is the outage alarm, which comes out of the frontend and out of /api/health; ConnectionManager keeps its own alarm for reconnect backoff.
> No new pill states. Missing credentials are not a special case: HQPTuner substitutes the stock defaults, so the credential-less path is reached only by explicitly emptying the env vars, and it reads Unreachable like any other unavailable lane.

Wire facts:

- A restore self-restarts the daemon in about 5.6 s (docs/architecture.md:17; docs/protocol.md:69).
- After a config-load POST the daemon answers on 4321 for about 0.3 s, refuses for a window, and answers `GetInfo` again about 3.4 s later (docs/protocol.md:80). That answering window is what a post-write wait must not mistake for the daemon having come back.
- After a restart 4321 refuses connections, then accepts and answers `GetInfo` at once; there is no accept-then-hang window (docs/protocol.md:21).
- One `GetInfo` per connection, so a handshake count is a connection count (tests/support/fake_control.py:334).
- The 4321 handshake that decides `reachable` is unauthenticated and cannot speak for the 8088 lane, which is Digest-authenticated (docs/architecture.md §2).
- Control API state is memory-only; a restart reverts it to the config file (docs/protocol.md:22).
