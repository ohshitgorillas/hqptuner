wire facts

- 4321 is unauthenticated and never restarts the daemon (docs/architecture.md:16).
- Persistent writes ride POST /restore, on which hqplayerd self-restarts in ~5.6 s
  (docs/architecture.md:17). Every path that restarts the daemon goes through that POST via
  `settle.restore`, and a preset save is one of them (hqptuner/presets/presetlane.py:268), so
  `restarting_daemon["dropped"]` is already 1 after `save_preset` and a case reads it before the load
  and waits for it to advance; the control lane is dropped the moment the POST returns
  (hqptuner/lanes/settle.py:52, manager `restarting`), so a case that needs a live connection for the
  load's restore to kill waits for the reconnect after the save first.
- Read-only use and all live settings work with no credentials (docs/architecture.md:37), so an
  install without them has no 8088 lane to wait for, ever.
- result="OK" is not proof; readback verifies (docs/architecture.md:26).
- The default poll interval is 2.0 s and the alarm threshold 15.0 s (hqptuner/config.py:49-50).
- /api/health `connected_at` is the manager's `readings.loaded_at` (hqptuner/api/routes/status.py:40),
  rewritten at the end of every connect and every poll; it is the wire-visible "a poll has
  completed" in line 2.
