## Wire and protocol facts

No daemon behavior bears on this block. The interface under test is the Claude Code `PreToolUse` hook contract: a hook receives one JSON payload on stdin carrying `tool_name`, `tool_input`, `cwd` and, on subagent calls only, `agent_type`; it prints a JSON object with `hookSpecificOutput.permissionDecision` set to `deny` to refuse the call, or prints nothing to let it through. An absent `agent_type` denotes the main agent. Session-wide wiring is `.claude/settings.json:5`; per-agent wiring is the `hooks:` frontmatter of an agent file.

## Applicable fixtures

`tests/gates/test_reviews_lane.py` supplies the house pattern for a lane test: the hook loaded by `importlib.util.spec_from_file_location` and its verdict function called directly, parametrized over `(agent, tool, path, expected)` tuples with `ids=`. Line 1 is a delta into its existing parametrize; lines 2, 3 and 5 need the process form instead, since `tests-lane._verdict` is module-private and `specs-lane.py` and `change-budget.py` are reached as processes. `.claude/hooks/budget_selftest.py` supplies `_said` and `_ran`, which build the transcript rows line 5 measures against. For line 4, `tests/gates/test_pair_merge_brief.py:105-116` (`_checkout`) and `tests/gates/test_pair_excision.py:119-132` (`_checkout`) build a throwaway checkout on `dev` carrying the driver, a `make check` that passes, a block file and a verdict file, then drive `scripts/pair.sh` in it by subprocess; line 4 is a delta into that pattern, and both of those checkout builders move the block file with it.

Line 4 is the fifth behavior line, one past the default cap of four (`.claude/commands/tests.md:46`). It is there because `open`'s spec-path contract is the whole of item 4's `pair.sh` half: the block's behavior lines are compared against nothing, so a driver that still accepted a caller-supplied path would leave the hole item 4 exists to close, and would ship green.
