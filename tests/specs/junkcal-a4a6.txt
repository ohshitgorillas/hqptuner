> Calibration capture for the HF filter auto-pilot. Capture only — no detection rule or threshold changes.
> Purpose: a corpus compared against albums known to have spurs, fake hi-res, or rising HF noise, to calibrate auto-pilot for consistency across albums. `junkadvisor` keeps every threshold as a module constant for exactly this; nothing today produces the captures.
> Env var in `hqptuner/config.py`, set in `docker-compose.yaml`. Unset = off; value is the destination directory. Owner-only: no UI, no copy, no changelog.
> Background task in the app lifespan beside `autopilotops.run`, 15 s tick, started only when the var is set.
> One file per playback period. The playback period is one album, therefore one production quality with consistent issues. While Nx content plays, append one row per tick, so drift within the album reads straight down the file.
> Row:
> - `MeteringReader.verdict()`, and what `autopilot.desired_junk_filter` resolved from it
> - `SpectralAggregate.window_min_db()`, full bin resolution above 13 kHz
> - wall timestamp, `agg.seconds` (engine coverage, not wall clock), `agg.frames`, engaged junk filter, active main filter, samplerate, bandwidth, bins
> The per-row spectrum is the windowed minimum: all three signatures are noise-floor properties present in every frame, so the minimum keeps them and drops intermittent music. Floor is 13 kHz because `LOSSY_WINDOW_HZ` starts there.
> `window_min_db()` returns None until `WINDOW_BLOCKS` × `BLOCK_SECONDS` of coverage, so early rows carry no spectrum. Write null and keep the row.
> Constraints: Nx gate already exists as `junkadvisor._eligible` — reuse it rather than a second rate test. `MeteringReader._agg` is private, so one read accessor is needed.
