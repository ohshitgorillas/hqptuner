kind: new

brief:
> Apod light tweak option: apod light only flashes with UNCORRECTED apod events. currently it flashes with all events, corrected or not.
> when a half apodizing filter is used, the light flashes at half brightness
> Apodizing indicator
> o Off
> o On for all events
> o On for uncorrected events
> An indicator light in the top bar flashes to indicate apodizing events. Brighter flashes indicate higher event density. When "On for uncorrected events", half-corrected events (e.g., from a half-apodizing filter) occur at half-brightness.

behaviors:

1. On "On for uncorrected events", at each of two bins (5 events/s, 12 events/s), a filter that is neither apodizing nor half-apodizing stands brighter than a half-apodizing filter at the same bin.
   kills: dims every stream by the same correction whatever the running filter's class, so the mode reads as a brightness trim rather than as a reading of what went uncorrected.
   bite: at {ms: 2000, n: 10} = 5 events/s, `--lamp` 0.522 at arg "0" and 0.522 at arg "2"; at {ms: 2000, n: 24} = 12 events/s, 0.747 at arg "0" and 0.747 at arg "2", both at preference "uncorrected" (`node --import ./tests/js/support/vendor-resolve.js --test /tmp/claude-1000/-srv-hqptuner/d1ad76b1-0091-4351-bbed-fcf443727c75/scratchpad/probe.mjs`, second density `.../probe24.mjs`)
   existing: none, `grep -rn "apodLight" tests/` returns only tests/js/components/chrome/apodlamp.test.js:7,48,121,162, none of which names a running filter; `grep -rln "active_filter" tests/js` returns signalpath.test.js, store/health.test.js, store/filter-narrowing.test.js, none of which renders the lamp.

2. With a half-apodizing filter running, at each of two bins (5 events/s, 12 events/s), the lamp on "On for uncorrected events" stands at half the brightness that same bin stands at on "On for all events", to within 0.001.
   kills: reads the two class flags full-first, so a record carrying both bits scores as fully corrected, taking the lamp dark where the owner asked for half.
   bite: at 5 events/s, `--lamp` 0.522 at preference "all" and 0.522 at "uncorrected"; at 12 events/s, 0.747 at "all" and 0.747 at "uncorrected", running filter at arg "2" (`node --import ./tests/js/support/vendor-resolve.js --test /tmp/claude-1000/-srv-hqptuner/d1ad76b1-0091-4351-bbed-fcf443727c75/scratchpad/probe.mjs`, second density `.../probe24.mjs`)
   existing: none, same grep as line 1.

3. With a full apodizing filter running, at each of two bins (5 events/s, 12 events/s), the lamp stands fully dark on "On for uncorrected events" while standing above dark on "On for all events".
   kills: keeps publishing the density the bin scored whatever the mode, so a fully corrected stream flashes as brightly as an uncorrected one.
   bite: at 5 events/s, `--lamp` 0.522 at preference "all" and 0.522 at "uncorrected"; at 12 events/s, 0.747 at "all" and 0.747 at "uncorrected", running filter at arg "1" (`node --import ./tests/js/support/vendor-resolve.js --test /tmp/claude-1000/-srv-hqptuner/d1ad76b1-0091-4351-bbed-fcf443727c75/scratchpad/probe.mjs`, second density `.../probe24.mjs`)
   existing: none, same grep as line 1.

4. On "Off" the rendered chrome carries zero lamp elements, whatever the current track has apodized.
   kills: treats any stored preference value as on, so the mode that switches the indicator off leaves it in the chrome.
   bite: element `data-testid="apod-lamp"` present carrying `--lamp` 0.522 at preference "off", one bin of {ms: 2000, n: 10} = 5 events/s (`node --import ./tests/js/support/vendor-resolve.js --test /tmp/claude-1000/-srv-hqptuner/d1ad76b1-0091-4351-bbed-fcf443727c75/scratchpad/probe.mjs`)
   existing: tests/js/components/chrome/apodlamp.test.js::test_the_lamp_does_not_render_when_the_preference_is_off

wire and protocol facts:

- `<GetFilters/>` returns `<FiltersItem index name value arg description/>`; `arg` is a flags bitfield, bit 0 (`0x00000001`) = apodizing (docs/protocol.md:228). Bit 1 is half-apodizing; the live daemon serves the field as a string, full "1", half "2", neither "0" (tests/js/components/controls/combobox-apod.test.js:15-17, the convention the existing apodizing-badge fixtures already serve).
- The Status frame carries `apod`, a cumulative apodizing-event counter, and `active_filter`, the running filter's raw engine name (docs/protocol.md:203). Filter facts join to it by that name (docs/architecture.md §2, running engine is enumeration authority).
- The lamp's brightness is a rate, not a count: a bin covers 1 s in LIVE and 2 s elsewhere, and the same music must read the same at both cadences (already pinned by tests/js/components/chrome/apodlamp.test.js:128).
