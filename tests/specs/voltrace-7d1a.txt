wire and protocol facts:

- The playing volume is a live 4321 value: `<Volume value="dB"/>` sets it and State reports it back under the `volume` attribute (docs/protocol.md §6; hqplayerd-readme.txt §1.13 for the fixed-volume element that suppresses it). result="OK" is not proof of application — the State readback is, which is why the level asked for and the level reported back are two values and not one.
- Volume control can be absent: VolumeRange reports enabled="0" on the fixed-volume and no-volume paths, and State then carries no `volume` attribute at all (docs/protocol.md §6). The fake answers `<Volume result="Error"/>` on that path (tests/support/fake_control.py:393-394).
- The startup volume is a different mechanism: the config-file field `<defaults volume="..."/>`, which reaches the daemon only over the restore lane and takes effect at boot (hqplayerd-readme.txt §1.3). A preset load restores the whole config and restarts the daemon (docs/architecture.md §7, restore-only preset model), so the engine's answers and the config file are two separate readings taken after that restart.
- A fully routable edit set applies over the 4321 control lane and never restarts the daemon or writes the config file; one restore-lane field sends the whole batch to the restore lane instead (docs/settings-classification.md; hqptuner/lanes/writer.py module docstring). So a live-only apply and a persistent apply are two different paths through one route.
- The event log is append-only JSON Lines, one record per line under a ts/seq/event envelope, off unless HQPTUNER_DEBUG_LOG names a path; a disabled instance is AuditLog(None) and its emitters are no-ops (docs/architecture.md §8). The vocabulary is the contract and is what tests assert; log *text* stays off-limits per docs/testing.md rule 1.
