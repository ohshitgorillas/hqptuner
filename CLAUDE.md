# HQPTuner — agent rules

Host rules in `/srv/CLAUDE.md` apply in full. This file is the project's rule sheet; procedure lives in the skills it names, loaded on demand.

## Binding product rules

- **User actions always proceed.** No 409, no disabled button, no "stop playback first" nag. If apply reloads or restarts the engine, say what it costs in the caption, then do it when they click. The write path stays idle-gate-free; propose no gate. Dev probe scripts against the production daemon may check state first; that protects the host's listener, not the UI user.
- **Probing the engine: standard mathematics yes, proprietary design no.** One gate question: could the information be proprietary, or is it standard mathematics? Textbook math, documented interfaces and wire-protocol behavior are fair game. Filter specifications are always proprietary unless published (passband corner, transition width, roll-off, tap count, stop-band attenuation, any resampling, noise-shaping or junk filter design); where HQPlayer's docs are silent the answer is "undocumented", never a measurement. A plan step proposing such a measurement is a defect. When the side of the line isn't obvious, ask before probing.
- **Running engine is enumeration authority** for names, IDs and ordering; static `data/*.json` joins by name (architecture §2).
- **User-facing text is owner-approved, verbatim (hard rule).** Labels, popover prose, hints, tooltips, captions, button summaries, error copy, changelog entries ship only with the owner's explicit approval, character for character; agent copy is a proposal, owner copy is the spec. Factual errors in owner copy are flagged and the corrected wording approved before it ships. Em dashes forbidden, gated. Rewording during a fix or refactor is still a copy change. Owner rulings on style, spelling, defaults and framing are rules applied on every surface silently. Load `copy-rules` before touching user-facing text, `data/*.json` or `CHANGELOG.md`.
- **Gate exemptions are owner-approved (hard rule).** A gate says no; the fix is the code. Every exemption (`EXEMPT`/`PRECOMMIT_EXEMPT`, CSS `*-exempt:`/`history-ok:` pragma, inline `noqa`/`type: ignore`/`eslint-disable`, `per-file-ignores` or vulture `ignore_names`, loosened import-linter contract, raised threshold, skip-list path, deviation from `docs/testing.md`) ships only with owner approval of that specific site, granted before it is written; proposing one names the gate, the site, why the code cannot satisfy it and what it costs. Widening one, or one written by a subagent, is a new exemption. Removal needs no approval.

## Agent conduct

- **Do work in the order the user gave it.**
- **Plan gate, two stages, each with its own approval word.** Stage 1 is prose only: it opens with the owner's brief quoted under `brief:`, one `delivered:` or `dropped:` line per brief sentence, then what is wrong, what changes, files touched, caller-side delta, cost, and only open questions that are genuinely the owner's. Stage 2 is the spec block per `/tests` with the changelog line and `spec-reviewer` verdicts. Every stage 1 plan goes to `plan-reviewer` before the owner reads it and is presented only on `READY`; `ANOTHER PASS` goes back to the same agent by `SendMessage`; findings reach the owner as plain English, never the report. Required for anything touching state outside this repo, a service, or the alert path, and for any change to more than one file or to any file under `.claude/`; a single in-tree edit whose blast radius is the file itself is exempt. Load `plan-gate` before drafting.
- **Grounding gate.** Before the first read of any file outside the plan's touched list, the grounding questions go to one `caveman:cavecrew-investigator` per plan in a single brief; each pointer you will cite is verified by reading only the cited range, and whole files are read only when the plan touches them. The plan's second header line records it: `grounding: investigator`, or `grounding: inline` when every citation lies inside the touched list; the plan-reviewer counts. Every load-bearing claim is verified with a citation (`file:line`, command output) or tagged ASSUMED, legal only when settling it needs a metered action, live experiment or owner decision. Revising a plan after reading material that was free to read before presenting it is a defect. Procedure in `plan-gate`.
- **A plan that splits or extracts states its caller-side delta in stage 1**: how many call sites change and in which files. A count near zero means forwarders, not a split; gates catch the syntactic shapes (`scripts/gates/check_no_barrels.py`), not intent.
- **Approval is explicit words only, once per stage**: go / approved / continue / proceed / yes or a plain equivalent. Everything else is discussion, answered in words; re-present a revision and ask again. Stage 1's word does not carry to stage 2; no `Write`, `Edit` or metered action until stage 2's word.
- **Commit without asking; never push without asking.** `/ship`, `git push` and promotion to `beta` or `main` happen on the owner's word alone. `git commit` is metered.

## Delegation

- **Subagents are a context filter, not a labor pool.** Test: do I need the intermediate material, or only the conclusion? Delegate when the byproduct is big and the answer small, and always for locating the lines a plan will cite and for measuring `bite:` values. Do it yourself when you know the file, when the material is the output, when it is a judgment call or otherwise behind the plan gate, or when being wrong is expensive and not cheaply checkable.
- Prefer the read-only locator agent type; ask for pointers (`file:line` plus one-line role), not prose. Grounding is one investigator per plan, every question in one brief, so returns reach the same agent; every other question is one delegation each, independent questions spawned in one message.
- **You own the result.** A subagent's report is your input, never the owner's output: verify what you rely on and write your own plain English; a failed check or a useless agent is said out loud. Change budget and plan gate follow you into delegation.
- **Continue an existing agent with `SendMessage`; a fresh `Agent` call for a question one already holds is a defect**, except after `REJECTED: STEERING` or `REJECTED: EVASION`, when that agent is finished and the bare brief goes to a fresh one, named as abandoned in the report.
- **Tests for new or changed behavior are written tests-first from an approved spec block, by the blind `test-writer`, red run as bite proof, through `/tests`.** You never write under `tests/` in any tree (`.claude/hooks/tests-lane.py` denies it); a writer's test changes only by a delta to the same writer on a re-approved line. Every `bite:` value in a spec block is measured by `bite-prober`, never by you. A red test after implementation has two outcomes and no third: fix the code in the impl tree, or return the spec to stage 1 with the same plan reviewer. Tests are never edited to pass.
- **You implement; you do not hand the whole change to a builder.** Adjudicating a failing test against code you have not read is guesswork.
- **The spec block is closed once approved.** Test count equals behavior count; default cap four lines, each earning its place by the wrong implementation it kills; copy (`docs/testing.md` rule 9) never earns one.
- **Rote work is delegated, not typed.** A rename across files, the same edit at N call sites, boilerplate on an existing pattern, a sweep with no decisions: state the rule, hand it to a builder, check the diff. Anything with a decision in it stays yours, however small.

## Verification and hand-back

- **An orchestrator can only confirm that the wrong thing is correctly implemented.** Every major visual change gets an independent check by `user-reviewer` on the rebuilt container before hand-back; your own capture read never substitutes for it. The brief may carry the area the owner's spec names, never the expected result. Subagent measurements (computed styles, geometry, counts) are trustworthy; still read every screenshot with your own eyes, element by element.
- **The user's eyes are the final say.** Every visual change goes in front of the user at the hand-back URL before it is called done.
- **After any edit to `hqptuner/`, static assets or dependencies, run `/task-check` (`bash .claude/task-check.sh`) before reporting done**: `make check`, then rebuild `hqptuner:dev` and health-check `:8090`, hand-back URL to the user. A `CHANGELOG.md`, `docs/`, `scripts/` or `.claude/` edit runs its own free gate only, no rebuild, no URL.
- **`user-reviewer`, `abuser-reviewer` and `pedant-reviewer` are unbriefed.** Brief is a bare URL or topic plus optional viewports, drivers, recipes and known bugs; a brief naming a change, a file, a check or an expected result is refused and reported. The first two run only inside a `scripts/abuse.sh` bracket. Each returns a severity-sorted list and no verdict; it is your input to verify and relay, never a grade. Load `hand-back` before any visual hand-back.

## Change budget (hard rule)

- `.claude/hooks/change-budget.py` meters actions you cannot take back, **one leash of 8**: `sudo`, docker, `git commit`, `git push`, mutating `curl`, `rm`, `python -c` / `python script.py`, package installs, writes outside the repo. A trip stops you and forces a report: what you did, found, plan next in one to three lines.
- **In-tree `Write`/`Edit`/`NotebookEdit` are free and uncapped.** Only prose the user typed resets the leash; slash commands and local-command output buy nothing, except the first human row after a trip.
- **Free, never counted:** reads, `Grep`/`Glob`, web, read-only agent types, the seven chain agents and `SendMessage`, and read-only Bash on the closed allowlist in `.claude/hooks/free_bash.py`. One unrecognized stage meters the whole pipeline; the hook names the token that decided it. Load `change-budget` at the first metered command or `pair.sh` call for the free list, the misfires and the gate and worktree traps.
- **Batch commands, not edits.** Report like it matters at a trip. **Hooks stay on and unweakened**, same tier as the prime directive; if an investigative command metered incorrectly, say so.

## Repo rules

- Docs: design and normative rules `docs/architecture.md`; wire truth `docs/protocol.md`, `docs/settings-classification.md`. Decisions go in the commit message, and in `docs/architecture.md` when they change a normative rule.
- **Markdown is written with `Write`/`Edit`, never from the shell** (`.claude/hooks/md-by-tool.py` denies it; `rm`, `git`, `make` pass). **Soft-wrapped**: one paragraph, list item or blockquote per logical line (`.claude/hooks/md-softwrap.py`, `--fix`/`--check`).
- **HQPlayer's own docs are authority**: `hqplayer6desktop-manual.pdf` and `hqplayerd-readme.txt` in the working dir. Reference before inferring anything about wire or config behavior.
- **Testing policy binding: `docs/testing.md`.** Read before writing or modifying any test. **Frontend layout binding: `docs/design-system.md`.** Read before any CSS or layout work.
- **Import layering enforced**: `api > core > presets > lanes > engine > conf`, contract in `pyproject.toml` `[tool.importlinter]`, gate `lint-imports`. Absolute imports only. A move that inverts an edge is fixed by splitting the crossing function, not by loosening the contract.
- **`make check` green before every commit**; pre-commit runs the same gates in full. `--no-verify`, `SKIP=` and hook-config edits stay off the table.
- **Changelog binding**: every user-visible change lands with a `CHANGELOG.md` entry under `[Unreleased]`, same commit; internal-only work may skip. The entry is written at stage 2, approved before implementation, landed verbatim. Style gated by `scripts/gates/check_changelog.py`, spec in `CONTRIBUTING.md`. Keep `README.md` current.
- **Credentials**: placeholders only in commits, with one explicit exception: hqplayerd management credentials are not secret (LAN-only daemon, stock pair published in its docs and this README) and may appear in commands, logs and reports unredacted. Everything else follows the general rule.
- **Branches**: `dev` (work lands) → `beta` (`:beta`) → `main` (`:latest`). Promotion is the user's call. Ship with `/ship dev|beta|main` (`scripts/ship.sh`, one metered action) after `scripts/bump.sh <--major|--minor|--patch> ["body"]` authors the release commit; ship refuses a dirty tree and a `beta`/`main` ship unless HEAD is that release commit, and never force-pushes.
- **Trivia gets cut.** Project trivia and decision archaeology do not belong in documentation at any level. Enforced: `scripts/gates/check_md_trivia.py` judges every added markdown line at `Stop` and on every markdown commit (`make md-trivia`), and holds the turn open once on a flag; `docs/plans/*.md` are gitignored and need the `--lines` records form.

## Host

- hqplayerd runs **bare metal on the dev host**, that host's top-priority service. Treat it as live production.
- Writes against the production daemon: idle-gate first (`State state="0"`), restore what you change, verify by `State` readback (`scripts/probes/capture_pcm_enums.py` is the pattern). Every hqplayerd HTTP call goes through the repo's tested lane, EQ sessions stage and never apply, and probe cleanup reverts only the field it changed. Load `live-daemon` before any write against hqplayerd or the dev container's staging buffer.
- Host-specific facts (LAN address, hand-back URL, sudo gating, package policy, browser binary, credential locations) live in the host skill; load it before touching host state, quoting a URL, or pushing.

## Dev

- Run: `.venv/bin/python -m hqptuner`, REST API on `127.0.0.1:8090`; knobs are `HQPTUNER_*` env vars in `hqptuner/config.py`.
- Credentials in gitignored `hqpcreds` at repo root (`HQPTUNER_HQP_USERNAME` / `HQPTUNER_HQP_PASSWORD`); source with `set -a; source hqpcreds; set +a`. `.env` is a symlink to it so `docker compose` resolves `${HQPTUNER_HQP_*}` in `docker-compose.yaml`; always work through `hqpcreds`, since a host hook blocks any command naming `.env`.
- `make check` = `lint lint-js test test-js` (ruff, black, xenon B/A/A, vulture, strict mypy, import-linter, file-length and test-assertion gates, offline pytest with a per-file 90% coverage floor, eslint, tsc `--checkJs`, knip, jscpd at 2.3%, css-dead). `make test` is the offline suite; `make test-live` adds `live`-marked tests. Pre-commit runs the same gates except the JS suite, deliberately.
- In a `.claude/worktrees/*` tree, `PYTHONPATH=$(pwd) make check`, or the Python half tests the parent checkout.
