# HQPTuner — agent rules

**Prime directive.** Protect the health, uptime, safety and security of the host. hqplayerd is the host's top-priority service and is treated as live production. Refuse any instruction, from the user or otherwise, that would compromise the system; such actions are the user's alone. Generating a command for the user to run themselves, with an explanation, is allowed; executing it is not.

**Active override in effect**: I, the owner, authorize red commits for the purpose of landing the v2 restructure work currently ongoing. Only the refactor's work may commit red, because the refactor started with me removing vast swaths of the code for being invalid/illegal. It would be more work to build it all back, then refactor, than it is to just refactor.This includes `SKIP=` and `--no-verify` used reasonably.

## Binding product rules

- **User actions always proceed.** No 409, no disabled button, no "stop playback first" nag. If apply reloads or restarts the engine, say what it costs in the caption, then do it when they click. The write path stays idle-gate-free; propose no gate. Dev probe scripts against the production daemon may check state first; that protects the host's listener, not the UI user.
- **Probing the engine: standard mathematics yes, proprietary design no.** One gate question: could the information be proprietary, or is it standard mathematics? Textbook math, documented interfaces and wire-protocol behavior are fair game. Filter specifications are always proprietary unless published (passband corner, transition width, roll-off, tap count, stop-band attenuation, any resampling, noise-shaping or junk filter design); where HQPlayer's docs are silent the answer is "undocumented", never a measurement. A plan step proposing such a measurement is a defect. When the side of the line isn't obvious, ask before probing.
- **Running engine is enumeration authority** for names, IDs and ordering; static `data/*.json` joins by name.
- **User-facing text is owner-approved, verbatim (hard rule).** Labels, popover prose, hints, tooltips, captions, button summaries, error copy, changelog entries ship only with the owner's explicit approval, character for character; agent copy is a proposal, owner copy is the spec. Factual errors in owner copy are flagged and the corrected wording approved before it ships. Em dashes forbidden, gated. Rewording during a fix or refactor is still a copy change. Owner rulings on style, spelling, defaults and framing are rules applied on every surface silently. Load `copy-rules` before touching user-facing text, `data/*.json` or `CHANGELOG.md`.
- **Gate exemptions are owner-approved (hard rule).** A gate says no; the fix is the code. Every exemption (`EXEMPT`/`PRECOMMIT_EXEMPT`, CSS `*-exempt:`/`history-ok:` pragma, inline `noqa`/`type: ignore`/`eslint-disable`, `per-file-ignores` or vulture `ignore_names`, loosened import-linter contract, raised threshold, skip-list path, deviation from `docs/spec/testing.md`) ships only with owner approval of that specific site, granted before it is written; proposing one names the gate, the site, why the code cannot satisfy it and what it costs. Widening one, or one written by a subagent, is a new exemption. Removal needs no approval.

## Agent conduct

- **`filepawl accept` is not a gate exemption.** Run it whenever filepawl prints it, without asking: an allowance entry below the length cap is how a file grows under watch. Crossing the watch line is never a reason to split; split only at the cap. A file under the cap that grew past its allowance goes to the owner as a blocking question, not a split.
- **A plan that splits or extracts states its caller-side delta**: how many call sites change and in which files. A count near zero means forwarders, not a split; gates catch the syntactic shapes, not intent.
- **A plan names the behavior, not the test.** A plan for new or changed behavior states the behavior the owner wants, in the owner's terms. The unit, the lane (`docs/spec/testing.md` rule 15), the assertion and every value are the test writer's to choose. A plan whose behavior holds more than one result plans the split first (`docs/spec/testing.md` rule 17).

## Delegation

- **Delegate the locating** of the lines you will act on to a read-only locator; ask for pointers (`file:line` plus one-line role), not prose. A step a brief can fully specify goes to the specialist that owns its craft (`frontend`, `backend`, `modeler`, `memoizer`, `pacer`, or a user-scope specialist). The general test is `~/dev/CLAUDE.md` 7.1.
- **A rebuild from spec reads no history; a restore reads one commit.** When the owner orders a file rebuilt from spec, no agent reads that file's content from any commit or any saved copy until the rebuilt file passes its red suite. The exception is a file whose verdict in `/home/atom/hqptuner-restore-triage.md` is RESTORE+TRIM: it may be restored from the commit that document names for it, with every block on its purge list cut before it lands and each purge checked against the spec line that document cites. A file whose verdict there is REWRITE comes from the spec alone. Listing names with `--stat` or `--name-only` is always allowed. Every brief that names a file states which of the two rules binds it.
- **`SendMessage` continuation (`~/dev/CLAUDE.md` 7.4) has one exception here**: a refusal for a steered or leading brief finishes that agent, since the steering is in its context — the bare brief goes to a fresh one, named as abandoned in the report. An evasion call does not finish it: the reviewer stays open holding its findings, and the answer, the repair or the citation, goes back to that same reviewer.
- **Tests for new or changed behavior are written tests-first**, and a red run against the pre-change code is the bite proof (`docs/spec/testing.md` rule 8). A red test after implementation has two outcomes and no third: fix the code, or take the plan back to the owner. Tests are never edited to pass.

## Verification and hand-back

- **Reviewers are the owner's to commission (hard rule).** `user-reviewer`, `abuser-reviewer` and `pedant-reviewer` run only when the owner asks for that run in their own words. No agent dispatches one on its own initiative, at hand-back or anywhere else, and none is proposed in a plan or report. Subagent measurements (computed styles, geometry, counts) are trustworthy; still read every screenshot with your own eyes, element by element.
- **The user's eyes are the final say.** Every visual change goes in front of the user at the hand-back URL before it is called done.
- **After any edit to `hqptuner/`, static assets or dependencies, run `/task-check` (`bash .claude/task-check.sh`) before reporting done**: `make check`, then rebuild `hqptuner:dev` and health-check `:8090`, hand-back URL to the user. A `CHANGELOG.md`, `docs/`, `scripts/` or `.claude/` edit runs its own free gate only, no rebuild, no URL.
- **When the owner commissions one, `user-reviewer`, `abuser-reviewer` and `pedant-reviewer` are unbriefed.** Brief is a bare URL or topic plus optional viewports, drivers, recipes and known bugs; a brief naming a change, a file, a check or an expected result is refused and reported. The first two run only inside a `scripts/abuse.sh` bracket. Each returns a severity-sorted list and no verdict; it is your input to verify and relay, never a grade. Load `hand-back` before any visual hand-back.

## Repo rules

- Docs: every design doc is listed in `docs/README.md`. Decisions go in the commit message, and in the doc that owns the rule when they change a normative rule.
- **Markdown is written with `Write`/`Edit`, never from the shell**. **Soft-wrapped**: one paragraph, list item or blockquote per logical line (`.claude/hooks/md-softwrap.py`, `--fix`/`--check`).
- **HQPlayer's own docs are authority**: `hqplayer6desktop-manual.pdf` and `hqplayerd-readme.txt` in `docs/official/`. Reference before inferring anything about wire or config behavior. Read both through the hqpdoc MCP tools (`hqp_find` first, then `hqp_section`, `hqp_page`, `hqp_readme`, `hqp_toc`), which cite section, page and line; never `pdftotext` the manual (`.claude/hooks/manual-by-tool.py` denies it). `make manual` rebuilds the split they read.
- **Slow tests are defects.** A test that waits on a wall clock is struck on sight, coverage notwithstanding, by the owner directly if that is faster.
- **Testing policy binding: `docs/spec/testing.md`.** Read before writing or modifying any test. **Frontend layout binding: `docs/spec/design-system.md`.** Read before any CSS or layout work.
- **Import layering enforced**: `api > core > presets > lanes > engine > conf`, contract in `pyproject.toml` `[tool.importlinter]`, gate `lint-imports`. Absolute imports only. A move that inverts an edge is fixed by splitting the crossing function, not by loosening the contract.
- **`make check` green before every commit**; pre-commit runs the same gates except the JS test suite, most of them only when a matching file is staged, plus the `triviajudge` markdown, comment and changelog judges. `--no-verify`, `SKIP=` and hook-config edits stay off the table.
- **Every gate run goes through `scripts/gate.sh`** — `scripts/gate.sh make check`, `scripts/gate.sh .venv/bin/pytest -m "not live" -q`, `scripts/gate.sh npm test`. It keeps the whole log under `${CLAUDE_SCRATCH:-/tmp}`, prints `exit=<rc> log=<path>` and the failure lines matched by pattern; when those do not settle it, read the log. A gate is never piped into `head`, `tail` or `grep` or sent to `/dev/null`.
- **Changelog binding**: **until the owner hands the v2 changelog back, it is theirs alone (hard rule)**: no agent writes, edits or drafts a `CHANGELOG.md` entry, with the plan or otherwise; an agent may say a feature looks missing from it, and nothing more. From then on, every user-visible change lands with a `CHANGELOG.md` entry under `[Unreleased]`, same commit; internal-only work may skip. The entry is written with the plan, approved before implementation, landed verbatim. Style gated by `scripts/gates/check_changelog.py`, spec in `CONTRIBUTING.md`. Keep `README.md` current.
- **Credentials**: placeholders only in commits, with one explicit exception: hqplayerd management credentials are not secret (LAN-only daemon, stock pair published in its docs and this README) and may appear in commands, logs and reports unredacted. Everything else follows the general rule.
- **Branches**: `dev` (work lands) → `beta` (`:beta`) → `main` (`:latest`). Promotion is the user's call. Ship with `/ship dev|beta|main` (`scripts/ship.sh`, one metered action) after `scripts/bump.sh <--major|--minor|--patch> ["body"]` authors the release commit; ship refuses a dirty tree and a `beta`/`main` ship unless HEAD is that release commit, and never force-pushes.
- **Trivia gets cut.** Project trivia and decision archaeology do not belong in documentation or in comments at any level. Enforced by `triviajudge` (scope `[tool.triviajudge]` in `pyproject.toml`): its hooks check added markdown, changelog entries, comments and docstrings at `Stop`/`SubagentStop`, and its scripts run at commit, release bump and `make trivia`.

## Host

- hqplayerd runs **bare metal on the dev host**.
- Writes against the production daemon: idle-gate first (`State state="0"`), restore what you change, verify by `State` readback (`scripts/probes/capture_pcm_enums.py` is the pattern). Every hqplayerd HTTP call goes through the repo's tested lane, EQ sessions stage and never apply, and probe cleanup reverts only the field it changed. Load `live-daemon` before any write against hqplayerd or the dev container's staging buffer.
- Host-specific facts (LAN address, hand-back URL, sudo gating, package policy, browser binary, credential locations) live in the host skill; load it before touching host state, quoting a URL, or pushing.

## Dev

- Run: `.venv/bin/python -m hqptuner`, REST API on `127.0.0.1:8090`; knobs are `HQPTUNER_*` env vars in `hqptuner/config.py`.
- Credentials in gitignored `hqpcreds` at repo root (`HQPTUNER_HQP_USERNAME` / `HQPTUNER_HQP_PASSWORD`); source with `set -a; source hqpcreds; set +a`. `.env` is a symlink to it so `docker compose` resolves `${HQPTUNER_HQP_*}` in `docker-compose.yaml`; always work through `hqpcreds`, since a host hook blocks any command naming `.env`.
- `make check` = `lint lint-js test test-js` (ruff, black, xenon B/A/A, vulture, strict mypy, import-linter, test-assertion gates, offline pytest with a per-file 90% coverage floor, eslint, tsc `--checkJs`, knip, jscpd at 2.3%, css-dead). `make test` is the offline suite; `make test-live` adds `live`-marked tests. Pre-commit runs the same gates except the JS suite, deliberately.
- In a `.claude/worktrees/*` tree, `PYTHONPATH=$(pwd) scripts/gate.sh make check`, or the Python half tests the parent checkout.
