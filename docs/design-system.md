# Design system — frontend layout (binding)

All visual work conforms or flags deviation. Never hardcode layout px — use tokens.

**CSS split by concern** under `hqptuner/static/css/`, none over 500-line gate. `<link>` order in `hqptuner/static/index.html` **is** cascade order. Never reorder. Add new module at position its rules need, not at end.

**Tokens (`hqptuner/static/css/tokens.css` `:root`):**
- Spacing scale `--sp-1..5` = 4/8/12/24/32. Every intra-row / inter-row gap references these.
- Widths: `--w-label` (12rem, shared label column), `--w-num` (short numerics + knob readouts), `--w-select` (28rem), `--w-select-wide` (30rem, long strings), `--w-path`.
- `--measure` (68ch) = single caption/description measure. `--w-app` (~1200px) = container cap.

**Typography, surfaces, corner radius, motion, spacing are tokens-only (binding).** Never write literal `font-size`, `font-weight`, `letter-spacing`, `border-radius`, `transition`, `gap`, `margin`, `padding` in `static/css/`, never raw colour outside `tokens.css`, never name elevation shade directly. `scripts/check_css_tokens.py` fails build on all (wired into `make lint-js` + pre-commit).

Every ladder below closed. **Pick by role, never by number** — two roles near same value fine; one role carrying two values is the drift these ladders stop.

- **Size** — pick token whose *role* matches text: `--fs-micro` (0.72, inline hints/credits) · `--fs-caption` (0.78, notes and descriptions) · `--fs-label` (0.85) · `--fs-body` (0.9, **default** for controls and field labels) · `--fs-head` (0.95, card-head/subhead) · `--fs-body-lg` (1) · `--fs-title` (1.1) · `--fs-brand` (1.25) · `--fs-readout` (1.5) · `--fs-glyph` (1.9, disclosure triangles). SVG text uses `--fs-svg-sm` / `--fs-svg` (px — SVG user units do not follow root rem).
- **Weight** `--fw-normal|medium|semibold|bold`. **Tracking** `--track-tight|caps|wide`, only ever with `text-transform: uppercase`.
- **Text greys exactly three, by role:** `--fg` = content user reads (values, control text, headings) · `--fg-2` = text that *names* things (labels, keys, column heads) · `--muted` = captions, notes, hints, units, disabled/off. Fourth shade = review flag.
- **Surfaces exactly four, by role:** `--surface-page` = page, and any chrome painting page lane · `--surface-card` = card or panel body, frame holding fields · `--surface-raised` = anything sitting *on* card: card and collapsible heads, controls, chips, popovers, plots · `--surface-well` = recessed reading surface, i.e. log tail and matrix paste box. Fifth shade = review flag.
- **Raw ladder (`--bg`, `--bg-2`, `--bg-3`) private to `tokens.css`.** `var(--bg*)` reference in any other module fails build. Naming surface by shade is how one card ends up different colour from card beside it — name role, shade follows.
- **Border, SVG `fill`/`stroke`, `box-shadow` are surfaces too.** Same four roles apply; these properties are where elevation drift hides.
- **Opacity exactly six — two ladders, one scale (binding).** *State* (is control in play?) dims whole control or region: `--o-disabled` (0.45, cannot be operated) · `--o-off` (0.55, control or chip switched off) · `--o-dim` (0.7, whole section off but still meant to be read). *Depth* (how far back does graphic sit?) separates layers of plot or diagram: `--o-back` (0.3, grid hairlines, excluded channels, fill washes) · `--o-mid` (0.6, reference marks — zero lines and ticks) · `--o-fore` (0.85, secondary graphic sitting just under primary). `0` and `1` stay literal — hidden and fully painted are not shading decisions. **Never dim *text* with opacity:** multiplied token is how one text role ends up with several effective greys, so text takes `--fg` / `--fg-2` / `--muted` and nothing else.
- **Text roles live in `typography.css`** — the one module loaded **last**, because it owns size and colour of every text role and must win over modules it replaced. New text takes role class (`.t-head`, `.t-eyebrow`, `.t-label`, `.t-caption`, `.t-micro`, `.t-value`); it does not get new rule with own size and colour.
- **Corner radius exactly six, by role:** `--r-xs` (3px, hairline marks — range tracks, tiny badges, legend swatches) · `--r-sm` (4px, small chips and swatches) · `--r-md` (6px, **default** — controls, inputs, fields, panels sitting on card) · `--r-lg` (8px, things holding other things — cards, plots, popovers) · `--r-pill` (999px) · `--r-circle` (50%). Gate checks *every* corner of shorthand, so `var(--r-md) 6px` fails.
- **Motion exactly two roles.** `var(--dur) var(--ease)` for state change — hover, focus, disable, open/close. `var(--sweep)` (1s ease-out) for live readout easing toward value poll refreshes every 2s: VU needle and meter fill. Duration and curve travel together in `--sweep` because splitting invites half-uses. Never transition on live drag.
- **Spacing exactly five steps, every `gap` / `margin` / `padding` references one:** `--sp-1` (4px, intra-control — label to its box, glyph to its text) · `--sp-2` (8px, control padding and inline groups) · `--sp-3` (12px, inter-control and card padding) · `--sp-4` (24px, inter-field and inter-column rhythm) · `--sp-5` (32px, major cluster separation). Gate rejects any **bare length** in spacing value rather than demanding every component be token — so `0`, `auto`, calc() arithmetic (`calc(var(--sp-3) * 1.1)`, `calc(var(--sp-4) / -2)`) stay legal, while half-tokenised `gap: var(--sp-2) 4px` fails. Value doing *job* rather than setting rhythm — clearance under fixed pending bar, room for `appearance:none` caret, size that must track own text — takes exemption.
- **Space between siblings has exactly one mechanism: the container's `gap` (binding).** Three rhythm roles alias the scale — `--rhythm-stack` (card to card down a tab body) · `--rhythm-row` (card to card across a row) · `--rhythm-field` (field to field down a card body). A `--rhythm-*` token is legal on `gap` / `row-gap` / `column-gap` and nowhere else, including a custom property re-exporting it under a local name; **no vertical margin may spend a spacing token at all**, only `0` or `auto`. Reason: a container gap and a child's vertical margin do not override, they *add*, and neither rule looks wrong on its own — `.top-row`'s `margin-bottom: var(--sp-4)` under `.tab-body`'s 8px gap left 32px under MODE/RATE/BACKEND against 8px between every other card pair, and `.card-grid`'s `margin-top` did the same at 16px. Both are fully tokenised, both name a real step; the defect is only visible if you already know what the parent spends. Same bug had been found and fixed by eye twice before (see notes in `narrowing.css`, `controls.css`), which is why it is a gate rather than a habit. Horizontal margins untouched — nothing competes with them, so `margin: 0 var(--gutter)` on a chrome row stays legal.
- Escape hatch for value that genuinely cannot be token: `/* token-exempt: <reason> */` on line. Reason required — exemption you cannot justify in a clause is value belonging in `tokens.css`. Enforced by regex, not substring: `/* token-exempt: */` buys no silence. For a vertical margin the clause must say why the space is **not** between siblings — spacing off a container edge, an optical nudge against a hairline, a negative pull — because if it is between siblings it belongs to the gap.

## Rules

- **Half-track rows cap controls to track.** `--w-select`/`--w-select-wide` legal only in full-span rows; inside `.pack` (or half-width `.card-grid` card) selects/text go `width:100%; max-width:100%; min-width:0`, grid items get `min-width:0`. 12rem-label + 28rem-select sum overflows half-track — column is cap.
- **Two-track section grid all-or-nothing** (`.pack`): short rows (numeric / checkbox / radio / narrow select) pack two-up; long-string rows opt into full-span via `.span` (schema `span: true` — device dropdowns, log path), never via `.field.wide`.
- **Pack by relatedness, not source order** (`.pack.chain`): sequential control chain stacks in LEFT column, secondary control goes right (e.g. filters `[1x, Nx]` left / dither|modulator right).
- **Two-column cards carry centred rule (binding).** *Every* full-width card with two internal columns draws 1px `var(--line)` hairline between them, and **every such rule sits on card's centre line** so they stack vertically down page. Three mechanisms, by shape:
  - *Fixed two-column split* (`.knob-cluster`, `.cluster-row`, `.xfc-cols`) — explicit 1px grid track: `grid-template-columns: 1fr 1px 1fr` + `<span class="col-rule">`.
  - *Multi-row two-track grid* (`.pack`) — one full-height `::before` on container's centre line, covers however many rows pack has.
  - *Border fallback* (`.pack.split`) — pull border into middle of gap with `margin-left: calc(var(--sp-4)/-2); padding-left: calc(var(--sp-4)/2)`. Never leave `border-left` at column edge: lands `gap/2` off-centre, visibly misaligns against every other rule.
  - Full-span row (`.span`) must not be struck through — masks rule over own height by painting its surface (`--surface-card` inside card, `--surface-page` on bare page). Only `.card` qualifies as card-like container here; keep it that way, or container falling off list paints page colour over card and reads as dark band across row.
  - **Exactly one rule per split.** Section marker drawing own `border-left` beside centred rule (`.cluster`, `.indent` inside `.pack`) reads as second divider — drop border there, let indentation alone carry nesting.
  - Below 1100px breakpoint split collapses to one column and rule hides.
- **Card rows fill container.** Paired cards share height via `.card-grid { align-items: stretch }`; `.card` carries `background: var(--surface-card)` (header `--surface-raised` + hairline) so stretched card's empty area reads as surface, not page-bg hole.
- **One card component, card markup written once (binding).** `Card` in `components/tabs/common.js` owns `.card` / `.card-head` / `.card-body`; nothing else may write them. Collapsible is not second component — it is `Card` handed `collapse` handle (`{open, onToggle}`, built from auto/override signal pair by `collapseFrom`), which turns head into toggle button and makes body conditional. Kept as one component because two drifted: open collapsible read as darker card than card beside it. `eslint-rules/no-hand-rolled-card.js` fails build on card classes written anywhere else; card whose structure genuinely does not fit takes file-level `eslint-disable` **with reason**, same escape hatch as `/* token-exempt: */`.
- **Class the JavaScript writes must have rule behind it (binding).** `scripts/check_css_classes.py` reads class names out of `static/**/*.js`, fails build on any no stylesheet defines — markup carrying class, every gate green, styling silently doing nothing. Follows helper one level (`class=${cls}`, `class=${fieldClasses(entry, k)}`), reports class at line writing it, not line using it. Out of scope by design, because name only exists at runtime: interpolated class (`vr-${which}`, `alert-${a.sev}`) and class read off data table (`class=${z.cls}`). **Reverse direction — selector no JS names — deliberately not gated and cannot be:** `class="swatch ${a}"` names class with no literal prefix at all, so accent swatches `.blue` / `.green` / `.amber` are live styling a dead-CSS gate would delete. Class that is *hook* rather than styling takes `// class-exempt: <reason>` on its line or one above.
- **Number with unit goes through `static/lib/units.js`.** Owns two decisions that drift otherwise: which unit frequency picks (`hz(n, dp)` — Hz below 1000, kHz above, MHz from DSD floor up, because every rate above it is 1-bit bitstream and MHz is idiom for those; PCM stays in kHz however high it goes), and whether decibel figure is signed. `db(v, dp)` is **absolute level**, never signs positive; `dbOffset(v, dp)` is **relative offset**, always does. **Precision deliberately stays caller's argument**, may differ site to site: `dp` is *ceiling* on decimals (trailing zeros trimmed — `96 kHz`, not `96.0 kHz`). No gate behind this. Two documented exceptions keep own formatters: plot drag HUD (`fmtF` / `fmtDeltaF` in `plots.js`) needs fixed decimals because centre-anchored and updates under pointer, so trimmed digit would re-centre line mid-drag; axis tick (`fmtHz`) writes different alphabet entirely (`1k`, not `1 kHz`). `dBFS` in `SpeakersDiagram.js` is different unit word, stays local. Wire formatters are separate job, must not route through this module — `fmtArg` in `matrixspec.js`, and fixed-precision gains in `binaural.js` / `xfeed.js` / `xfmode.js`, exist to round-trip byte-identically through daemon, not to be read.
- **Rhythm:** control→caption gap ≈ ⅓ of row→row gap (tight intra `--sp-1`, inter-field `--sp-4`). Captions cap at `--measure` and wrap — never truncate.
- **Container** `--w-app` ~1200px; below ~1100px viewport, sections fall back to single column (old layout is fallback, kept intact).
- Deliberate trailing half-cells (odd control count) allowed; unnameable blanks not.

## Definition of done (every tab @1280)

(a) nothing clips or overlaps; (b) each section fills both tracks or deliberately spans; (c) every card row's right edge flush with container; (d) all whitespace is page gutter, inter-track gutter, or caption margin — no unnameable blanks.

## Hand-back protocol for visual work (binding)

Before reporting ready, verify against FRESH screenshots at 1280, report PASS/FAIL per acceptance criterion, with measured pixel numbers for anything measurable (card bottom edges, control widths, edge alignments — measure DOM via headless chromium + playwright, not by eye). Measure **both accent themes and both hero states** — never "by construction". "Ready" with unverified or failing criterion is process failure regardless of how page looks.

## Regression guard

Any new control / row / section / card slots into token + grid system. New one-off pixel value in layout CSS is review flag by default.
