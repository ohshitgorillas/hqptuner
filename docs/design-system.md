# Design system — frontend layout (binding)

All visual work conforms or flags deviation. Never hardcode layout px — use tokens.

**CSS split by concern** under `hqptuner/static/css/`, none over 500-line gate. Four concern directories: `base/` (tokens, type, app shell), `controls/` (the input primitives), `cards/` (card frames and what sits in them), `features/` (one tab's own rules). `<link>` order in `hqptuner/static/index.html` **is** cascade order. Never reorder. Add new module at position its rules need, not at end.

**Tokens (`hqptuner/static/css/base/tokens.css` `:root`):**
- Spacing scale `--sp-1..5` = 4/8/12/24/32. Every intra-row / inter-row gap references these.
- Widths: `--w-label` (12rem, shared label column), `--w-num` (short numerics + knob readouts), `--w-select` (28rem), `--w-select-wide` (30rem, long strings), `--w-path`.
- `--measure` (68ch) = single caption/description measure. `--w-app` (~1200px) = container cap.

**Typography, surfaces, corner radius, motion, spacing are tokens-only (binding).** Never write literal `font-size`, `font-weight`, `letter-spacing`, `border-radius`, `transition`, `gap`, `margin`, `padding` in `static/css/`, never raw color outside `tokens.css`, never name elevation shade directly. `scripts/gates/check_css_tokens.py` fails build on all (wired into `make lint-js` + pre-commit).

Every ladder below closed. **Pick by role, never by number** — two roles near same value fine; one role carrying two values is the drift these ladders stop.

- **Size** — pick token whose *role* matches text: `--fs-micro` (0.72, inline hints/credits) · `--fs-caption` (0.78, notes and descriptions) · `--fs-label` (0.85) · `--fs-body` (0.9, **default** for controls and field labels) · `--fs-head` (0.95, card-head/subhead) · `--fs-body-lg` (1) · `--fs-title` (1.1) · `--fs-brand` (1.25) · `--fs-readout` (1.5). SVG text uses `--fs-svg-sm` / `--fs-svg` (px — SVG user units do not follow root rem).
- **Triangle marks are shapes, not glyphs (binding):** `--tri-sm` (0.28rem, narrowbar caret) · `--tri-md` (0.5rem, combobox trigger caret) · `--tri-lg` (0.6rem, disclosure: card head, group header, selection mark). Each is a square box carrying a `clip-path: polygon(...)`, so the box IS the ink and any rule that centers the box centers the mark. A text triangle cannot be centered that way: U+25BE's ink sits 0.047em below the center of whatever line box holds it, independent of `line-height`, so a box-centered character reads low wherever it sits. Direction is a class or an ARIA state, never a different character.
- **Weight** `--fw-normal|medium|semibold|bold`. **Tracking** `--track-tight|caps|wide`, only ever with `text-transform: uppercase`.
- **Text grays exactly three, by role:** `--fg` = content user reads (values, control text, headings) · `--fg-2` = text that *names* things (labels, keys, column heads) · `--muted` = captions, notes, hints, units, disabled/off. Fourth shade = review flag.
- **Surfaces exactly four, by role:** `--surface-page` = page, and any chrome painting page lane · `--surface-card` = card or panel body, frame holding fields · `--surface-raised` = anything sitting *on* card: card and collapsible heads, controls, chips, popovers, plots · `--surface-well` = recessed reading surface, i.e. log tail and matrix paste box. Fifth shade = review flag.
- **Raw ladder (`--bg`, `--bg-2`, `--bg-3`) private to `tokens.css`.** `var(--bg*)` reference in any other module fails build. Naming surface by shade is how one card ends up different color from card beside it — name role, shade follows.
- **Border, SVG `fill`/`stroke`, `box-shadow` are surfaces too.** Same four roles apply; these properties are where elevation drift hides.
- **`--surface-raised` carries an edge light, applied once (binding).** `--edge-light` is a 1px inset top highlight under 6% white; the single rule listing every selector that paints `background: var(--surface-raised)` lives in `aesthetic.css` and is the only place it is spent. It belongs to the *role*, not to any component — a raised element catches light on its top lip and a card does not, and that is what separates "sitting on" from "cut into" when every border is the same color all the way round. Two exclusions, both by definition: a **recessed** reading surface (range track, meter trough, volume-bar track) is lit from the wrong side, and an SVG `fill` user has no box to inset a shadow into. An element already spending `box-shadow` (`.multi-pop`'s `--shadow-pop`) writes both shadows into its own one value — a second rule would replace the first, not add to it.
- **Opacity exactly six — two ladders, one scale (binding).** *State* (is control in play?) dims whole control or region: `--o-disabled` (0.45, cannot be operated) · `--o-off` (0.55, control or chip switched off) · `--o-dim` (0.7, whole section off but still meant to be read). *Depth* (how far back does graphic sit?) separates layers of plot or diagram: `--o-back` (0.3, grid hairlines, excluded channels, fill washes) · `--o-mid` (0.6, reference marks — zero lines and ticks) · `--o-fore` (0.85, secondary graphic sitting just under primary). `0` and `1` stay literal — hidden and fully painted are not shading decisions. **Never dim *text* with opacity:** multiplied token is how one text role ends up with several effective grays, so text takes `--fg` / `--fg-2` / `--muted` and nothing else.
- **Text roles live in `typography.css`** — the one module loaded **last**, because it owns size and color of every text role and must win over modules it replaced. New text takes role class (`.t-head`, `.t-eyebrow`, `.t-label`, `.t-caption`, `.t-micro`, `.t-value`); it does not get new rule with own size and color.
- **Corner radius exactly six, by role:** `--r-xs` (3px, hairline marks — range tracks, tiny badges, legend swatches) · `--r-sm` (4px, small chips and swatches) · `--r-md` (6px, **default** — controls, inputs, fields, panels sitting on card) · `--r-lg` (8px, things holding other things — cards, plots, popovers) · `--r-pill` (999px) · `--r-circle` (50%). Gate checks *every* corner of shorthand, so `var(--r-md) 6px` fails.
- **Motion exactly three roles.** `var(--dur) var(--ease)` for state change — hover, focus, disable, open/close. `var(--sweep)` (1s ease-out) for live readout easing toward value poll refreshes every 2s: VU needle and meter fill. Duration and curve travel together in `--sweep` because splitting invites half-uses. Never transition on live drag. `var(--flow)` (6s) is the third and the only **loop**: ambient state depiction, currently the signal-path thread's drift while the engine plays. A loop answers to no user action, so it takes compositor-only properties (`transform`), stays slow enough not to read as a progress bar, and **must** be disabled under `prefers-reduced-motion: reduce` — there is no reduced version of an effect whose whole content is motion, so the element is simply not drawn.
- **Spacing exactly five steps, every `gap` / `margin` / `padding` references one:** `--sp-1` (4px, intra-control — label to its box, glyph to its text) · `--sp-2` (8px, control padding and inline groups) · `--sp-3` (12px, inter-control and card padding) · `--sp-4` (24px, inter-field and inter-column rhythm) · `--sp-5` (32px, major cluster separation). Gate rejects any **bare length** in spacing value rather than demanding every component be token — so `0`, `auto`, calc() arithmetic (`calc(var(--sp-3) * 1.1)`, `calc(var(--sp-4) / -2)`) stay legal, while half-tokenized `gap: var(--sp-2) 4px` fails. Value doing *job* rather than setting rhythm — clearance under fixed pending bar, room for `appearance:none` caret, size that must track own text — takes exemption.
- **Space between siblings has exactly one mechanism: the container's `gap` (binding).** Three rhythm roles alias the scale — `--rhythm-stack` (card to card down a tab body) · `--rhythm-row` (card to card across a row) · `--rhythm-field` (field to field down a card body). A `--rhythm-*` token is legal on `gap` / `row-gap` / `column-gap` and nowhere else, including a custom property re-exporting it under a local name; **no vertical margin may spend a spacing token at all**, only `0` or `auto`. Reason: a container gap and a child's vertical margin do not override, they *add*, and neither rule looks wrong on its own — `.top-row`'s `margin-bottom: var(--sp-4)` under `.tab-body`'s 8px gap left 32px under MODE/RATE/BACKEND against 8px between every other card pair, and `.card-grid`'s `margin-top` did the same at 16px. Both are fully tokenized, both name a real step; the defect is only visible if you already know what the parent spends. Same bug had been found and fixed by eye twice before (see notes in `narrowing.css`), which is why it is a gate rather than a habit. Horizontal margins untouched — nothing competes with them, so `margin: 0 var(--gutter)` on a chrome row stays legal.
- Escape hatch for value that genuinely cannot be token: `/* token-exempt: <reason> */` on line. Reason required — exemption you cannot justify in a clause is value belonging in `tokens.css`. Enforced by regex, not substring: `/* token-exempt: */` buys no silence. For a vertical margin the clause must say why the space is **not** between siblings — spacing off a container edge, an optical nudge against a hairline, a negative pull — because if it is between siblings it belongs to the gap.

## Rules

- **Half-track rows cap controls to track.** `--w-select`/`--w-select-wide` legal only in full-span rows; inside `.pack` (or half-width `.card-grid` card) selects/text go `width:100%; max-width:100%; min-width:0`, grid items get `min-width:0`. 12rem-label + 28rem-select sum overflows half-track — column is cap.
- **Two-track section grid all-or-nothing** (`.pack`): short rows (numeric / checkbox / radio / narrow select) pack two-up; long-string rows opt into full-span via `.span` (schema `span: true` — device dropdowns, log path), never via `.field.wide`.
- **Pack by relatedness, not source order** (`.pack.chain`): sequential control chain stacks in LEFT column, secondary control goes right (e.g. filters `[1x, Nx]` left / dither|modulator right).
- **Two-column cards carry centered rule (binding).** *Every* full-width card with two internal columns draws 1px `var(--line)` hairline between them, and **every such rule sits on card's center line** so they stack vertically down page. Three mechanisms, by shape:
  - *Fixed two-column split* (`.knob-cluster`, `.cluster-row`, `.xfc-cols`) — explicit 1px grid track: `grid-template-columns: 1fr 1px 1fr` + `<span class="col-rule">`.
  - *Multi-row two-track grid* (`.pack`) — one full-height `::before` on container's center line, covers however many rows pack has.
  - *Border fallback* (`.pack.split`) — pull border into middle of gap with `margin-left: calc(var(--sp-4)/-2); padding-left: calc(var(--sp-4)/2)`. Never leave `border-left` at column edge: lands `gap/2` off-center, visibly misaligns against every other rule.
  - Full-span row (`.span`) must not be struck through — masks rule over own height by painting its surface (`--surface-card` inside card, `--surface-page` on bare page). Only `.card` qualifies as card-like container here; keep it that way, or container falling off list paints page color over card and reads as dark band across row.
  - **Exactly one rule per split.** Section marker drawing own `border-left` beside centered rule (`.cluster`, `.indent` inside `.pack`) reads as second divider — drop border there, let indentation alone carry nesting.
  - Below 1100px breakpoint split collapses to one column and rule hides.
- **Card rows fill container.** Paired cards share height via `.card-grid { align-items: stretch }`; `.card` carries `background: var(--surface-card)` (header `--surface-raised` + hairline) so stretched card's empty area reads as surface, not page-bg hole.
- **One card component, card markup written once (binding).** `Card` in `components/common.js` owns `.card` / `.card-head` / `.card-body`; nothing else may write them. Collapsible is not second component — it is `Card` handed `collapse` handle (`{open, onToggle}`, built from auto/override signal pair by `collapseFrom`), which turns head into toggle button and makes body conditional. Kept as one component because two drifted: open collapsible read as darker card than card beside it. `eslint-rules/no-hand-rolled-card.js` fails build on card classes written anywhere else; card whose structure genuinely does not fit takes file-level `eslint-disable` **with reason**, same escape hatch as `/* token-exempt: */`. Head takes optional `subtitle` — feature's own prose under card's name, `.card-sub` + `.t-caption`, sourced through `noteFor(<key>)` (`store/prose.js`) and never a string written at call site. Belongs to card, not to row: card gated by master switch has one explanation, and under switch it read as caption on switch. Follows same descriptions pref as inline notes, so gate row carrying `hoverNote` loses its inline note and keeps hover.
- **Class the JavaScript writes must have rule behind it (binding).** `scripts/gates/check_css_classes.py` reads class names out of `static/**/*.js`, fails build on any no stylesheet defines — markup carrying class, every gate green, styling silently doing nothing. Follows helper one level (`class=${cls}`, `class=${fieldClasses(entry, k)}`), reports class at line writing it, not line using it. Out of scope by design, because name only exists at runtime: interpolated class (`vr-${which}`, `alert-${a.sev}`) and class read off data table (`class=${z.cls}`). **Reverse direction — selector no JS names — deliberately not gated and cannot be:** `class="swatch ${a}"` names class with no literal prefix at all, so accent swatches `.blue` / `.green` / `.amber` / `.violet` are live styling a dead-CSS gate would delete. Class that is *hook* rather than styling takes `// class-exempt: <reason>` on its line or one above.
- **Staged-edit highlight goes on the control, not the row (binding).** Control with border of its own recolors that border `var(--accent)` when its field is dirty — segment, select, number, text. Control with no border to recolor (checkbox, whose border already goes accent when *checked*; knob and slidernum, which have none) keeps row's inset ring, legal for them only because their control never fills its row. Reason: inset `box-shadow` paints on element's own background layer, strictly under descendants, so ring on a row a control fills is covered on every edge the control touches — hero MODE and BACKEND showed accent loop diving behind switch and re-emerging as empty trough beneath it, fully tokenized and green on every gate. Border cannot be overpainted: belongs to element it marks. `scripts/gates/check_css_dirty.py` fails build on widget kind with no marking, on marking rule that has gone missing, and on inset accent ring reaching any row outside three ring widgets; `/* dirty-mark-exempt: <reason> */` is escape hatch. A control that *conceals* dirty fields (a switch whose inactive side has staged edits — Loudness Bass|Treble) surfaces them with an accent `.seg-dirty-dot` inside the concealing button: staged edits must never be invisible.
- **Number with unit goes through `static/lib/units.js`.** Owns two decisions that drift otherwise: which unit frequency picks (`hz(n, dp)` — Hz below 1000, kHz above, MHz from DSD floor up, because every rate above it is 1-bit bitstream and MHz is idiom for those; PCM stays in kHz however high it goes), and whether decibel figure is signed. `db(v, dp)` is **absolute level**, never signs positive; `dbOffset(v, dp)` is **relative offset**, always does. **Precision deliberately stays caller's argument**, may differ site to site: `dp` is *ceiling* on decimals (trailing zeros trimmed — `96 kHz`, not `96.0 kHz`). No gate behind this. Two documented exceptions keep own formatters: plot drag HUD (`fmtF` / `fmtDeltaF` in `plots.js`) needs fixed decimals because center-anchored and updates under pointer, so trimmed digit would re-center line mid-drag; axis tick (`fmtHz`) writes different alphabet entirely (`1k`, not `1 kHz`). `dBFS` in `speakers/Diagram.js` is different unit word, stays local. Wire formatters are separate job, must not route through this module — `fmtArg` in `matrixspec.js`, and fixed-precision gains in `binaural.js` / `xfeed.js` / `xfmode.js`, exist to round-trip byte-identically through daemon, not to be read.
- **Segmented switches have exactly ONE size (binding).** Base `.segment .seg` rule in `controls-fields.css`: padding `--sp-2`/`--sp-4`, type `--fs-body-lg`. Named exemptions: hero `.seg-box` segments (`hero.css`) and Matrix `.matrix-switcher` banner (`speakers.css`). No new per-context segment size rules.
- **Rhythm:** control→caption gap ≈ ⅓ of row→row gap (tight intra `--sp-1`, inter-field `--sp-4`). Captions cap at `--measure` and wrap — never truncate.
- **Container** `--w-app` ~1200px; below ~1100px viewport, sections fall back to single column (old layout is fallback, kept intact).
- Deliberate trailing half-cells (odd control count) allowed; unnameable blanks not.

## Definition of done (every tab @1280)

(a) nothing clips or overlaps; (b) each section fills both tracks or deliberately spans; (c) every card row's right edge flush with container; (d) all whitespace is page gutter, inter-track gutter, or caption margin — no unnameable blanks.

## Hand-back protocol for visual work (binding)

Before reporting ready, verify against FRESH screenshots at 1280, report PASS/FAIL per acceptance criterion, with measured pixel numbers for anything measurable (card bottom edges, control widths, edge alignments — measure DOM via headless chromium + playwright, not by eye). Measure **both accent themes and both hero states** — never "by construction". "Ready" with unverified or failing criterion is process failure regardless of how page looks.

## Regression guard

Any new control / row / section / card slots into token + grid system. New one-off pixel value in layout CSS is review flag by default.
