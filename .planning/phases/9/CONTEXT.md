## Durable decisions

- D-01 (Queue, never refuse): a write lane that arrives while another holds the apply lock waits its turn and then runs; no 409, no busy answer and no new refusal is added. Evidence: `CLAUDE.md` ("User actions always proceed"), `.planning/security/DISPOSITIONS.md` F-012, `hqptuner/api/routes/apply.py:106-130`.
- D-02 (Lock scope): one lock serializes every lane that pushes `POST /restore` or reloads the engine: `POST /api/config/apply` (with its preset switch and auto-save fold), `POST /api/profile/load` and `/save` (the save's `_mirror` restore), `POST /api/engine`, `POST /api/restore` and `POST /api/speakers`. It is taken once at the outermost user operation, and nested steps run inside that hold, since `asyncio.Lock` is not reentrant. LIVE 4321 writes (`/config/live`, `/volume`, livepreset apply, matrix profile, autopilot) stay outside it, under the per-command socket lock and the phase 7 readiness gate. Stage and discard never wait on it. Rejected: locking each `settle.restore` call (passes still interleave), and putting LIVE writes behind it (volume waits on a restore). Evidence: `hqptuner/lanes/settle.py:50` and its callers `hqptuner/lanes/http/restore.py:351`, `hqptuner/presets/presetlane.py:158,334`, `hqptuner/lanes/http/engineattrs.py:116`, `hqptuner/api/routes/config.py:399`; `hqptuner/core/applyops.py:150-173`; `hqptuner/engine/control.py:124`; `hqptuner/api/readygate.py:19-31`; phase 7 D-02.
- D-03 (F-029 shared buffer): the pending buffer stays one app-wide object, and the clause "one client's field applies under another's press" is declined. Owner ruling, quoted: "Keep shared, decline clause". Rejected: per-login-session buffers (break reload recovery and cross-tab staging, and need a client identity the app lacks). Evidence: `hqptuner/api/factory.py:87`, `hqptuner/api/routes/pending.py:49-53`.
- D-04 (F-030 rollback): no rollback is added; an unconverged outcome returns its report and keeps the buffer for a retry, as today. Owner ruling, quoted: "No rollback, decline". Rejected: automatic rollback (an unasked restart that races a queued apply), and naming the copy in the report. Evidence: `hqptuner/lanes/http/restore.py:271-286`, `hqptuner/api/routes/pending.py:107-116`.
- D-05 (F-030 copies): each user operation writes exactly one safety copy, the daemon's state before its first restore; later passes and the restore after a preset switch write none. Copies are dated files in `backup_dir`, named from the injectable `mgr.clock`, and the 5 most recent are kept (about 9 MB each on this host). Owner choice: "Dated, keep last 5". Rejected: keeping 3, and two fixed slots. Evidence: `hqptuner/presets/presetops.py:272-288`, `hqptuner/lanes/http/restore.py:234-240,328-329`, `hqptuner/presets/presetlane.py:152-154`, `hqptuner/core/clock.py`, `hqptuner/presets/store/export.py:55-71`.
- D-06 (F-031 atomic write): one shared helper writes a uniquely named temp file in the target's directory, fsyncs it, `os.replace`s it over the target and fsyncs the directory. Every JSON store, the preset XML, `store.json` and `active.json`, the parked filter files, the safety copy and `ConnectionStore.write` use it. `connection.json` keeps its phase 6 guarantee (0600 even over a wider-mode leftover temp file). Owner choice: "fsync file and dir". Rejected: rename without fsync (a power loss can leave a zero-length store), and the fixed `<name>.tmp` (concurrent writers unlink each other's temp). Evidence: `hqptuner/presets/store/presets.py:214,258,292,316`, `hqptuner/presets/store/live.py:263`, `hqptuner/presets/store/favorites.py:173`, `hqptuner/presets/store/descriptions.py:288`, `hqptuner/presets/store/autopilot.py:138`, `hqptuner/presets/store/narrowing.py:313`, `hqptuner/presets/store/matrixmode.py:173`, `hqptuner/presets/store/filterpark.py:162`, `hqptuner/presets/presetops.py:284`, `hqptuner/core/connection.py:126-139`, `hqptuner/unwritable.py`, `pyproject.toml:288-303`.
- D-07 (F-031 store lock): each store instance holds one `threading.Lock` around its whole read-modify-write; `PresetStore` takes one lock for its directory (XML files, `store.json`, `active.json`). One instance per process makes a per-instance lock enough. Rejected: moving the store routes to `async def` with `asyncio.Lock`. Evidence: `hqptuner/api/factory.py:91-96`, `hqptuner/presets/presetops.py:134-142`, `hqptuner/__main__.py:37-44`, `hqptuner/presets/store/favorites.py:166-174`, `hqptuner/presets/store/presets.py:287-317`.

## Decisions

- D-08 (Selective clear): the apply runs on its own copy of the staged set, not on `store.http` and `store.live`. A converged apply removes from the buffer only the entries it applied, and only where the buffered value still equals the applied value; a field staged or re-staged during the apply stays staged. The SPA re-reads pending after every apply, so no client change is needed. Evidence: `hqptuner/api/routes/apply.py:121-129`, `hqptuner/api/routes/pending.py:60-66`, `hqptuner/core/applyops.py:164-165`, `hqptuner/static/store/actions.js:338`.
- D-09 (Park clear): after a converged apply, the filter park releases only the parked files that apply carried; an upload parked during the apply survives for the next one. Evidence: `hqptuner/presets/presetops.py:102-106,157-163`, `hqptuner/lanes/http/restore.py:343`, `hqptuner/presets/store/filterpark.py:143-163`.
- D-10 (Copy validation): bytes that are not a readable settings archive (an empty `/backup` body, a non-zip) never replace a stored copy; the operation then fails through its existing downstream refusal, with no new text. Evidence: `hqptuner/presets/presetops.py:281-284`, `hqptuner/conf/presetzip.py:202-204`, `hqptuner/conf/engineconf.py:266-274`, `hqptuner/static/store/actions.js:316-317`.
- D-11 (Corrupt store): `read_stamped` keeps refusing an unparseable file with the existing `StoreCorruptError` copy, and writes keep reading first; no API path overwrites a corrupt store. Evidence: `hqptuner/presets/store/jsonfile.py:29-40,61-68`, `hqptuner/presets/store/live.py:255-263`.
- D-12 (Superseded tests): tests that pin the single slot or non-zip backup bytes are named in the plan as superseded behavior, never edited quietly to pass. Evidence: `tests/presets/test_backup_persist.py:86-87`, `tests/apply/test_http_apply.py:111-118`, `tests/presets/test_state_export.py:100,146-150`, `tests/audit/test_audit_wiring.py:96`.
- D-13 (Record and constraints): one `.planning/security/DISPOSITIONS.md` entry per finding in the existing shape, each partial decline quoted inside its finding; no new module in `hqptuner/api/routes/`, `hqptuner/engine/`, `hqptuner/conf/` or `hqptuner/static/store/` (at filepawl's cap of 15), and top-level `hqptuner/` has one slot left; race proofs force overlap with injected seams (`asyncio.Event`, the fake 8088 daemon, `mgr.clock`), never sleeps or thread timing; any new user-facing text and the `### Security` changelog entry are owner copy, approved before implementation. Evidence: phase 8 D-16, `.filepawl.toml`, `docs/testing.md:19-27`, `tests/support/fake_http.py`, `tests/engine/test_control_queued.py`, `CLAUDE.md`.

## Acceptance criteria

- [ ] AC1: while one apply is running, a second apply, preset load or `/api/restore` request waits and then completes with no 409, and the daemon receives the two operations' `/restore` pushes in sequence, never interleaved
- [ ] AC2: a field staged during an apply, or re-staged with a new value, is still in `GET /api/config/pending` after that apply converges; a filter uploaded to the park during an apply is still parked after it
- [ ] AC3: one apply that takes two restore passes leaves exactly one new safety copy, holding the pre-apply state; after 6 operations the 5 most recent copies remain; an empty or non-zip `/backup` body replaces no stored copy
- [ ] AC4: two concurrent writers to one JSON store both land and the file always parses; a write killed between the temp write and the rename leaves the previous file whole; `connection.json` stays mode 0600
- [ ] AC5: `.planning/security/DISPOSITIONS.md` has one entry each for F-029, F-030 and F-031; each fixed part names its commit and a proof that fails against the pre-fix code, and the per-client buffer and rollback declines quote the owner's ruling
- [ ] AC6: `make check` is green, and `check`, `e2e`, `smoke`, `lifecycle-deb`, `lifecycle-rpm`, `smoke-macos` and `smoke-windows` pass on the phase's last `dev` commit (ci: check, e2e, smoke, lifecycle-deb, lifecycle-rpm, smoke-macos, smoke-windows)

## Flagged assumptions

- `os.replace` over a file another handle holds open on the Windows build can fail with `PermissionError` on NTFS, and the stores' Windows readers were not checked - Unclear (research); if wrong: D-06's write fails on Windows under a concurrent read, caught only by `smoke-windows` if at all.
- A `threading.Lock` taken from event-loop code (`presetops.py:183-224`, `presetlane.py:159`) as well as from threadpool `def` routes cannot stall the loop for long, given the AnyIO default limiter - Unclear (research); if wrong: D-07 blocks the event loop while a threadpool writer holds a store lock.
- Directory fsync is a no-op or unsupported on NTFS - Likely; if wrong: D-06's helper needs a per-platform branch.
- Every lane that pushes `/restore` goes through `lanes/settle.py:50` - Likely; if wrong: a lane outside D-02's set keeps the interleaving.
