# Phase 8: Config write path and input validation - Plan 1: The XML write path and staged values

## Goal

Findings F-006, F-007, F-010, F-011, F-012, F-013, F-014, F-016, F-018, F-019, F-026, F-032 and F-033 are each fixed or carry an owner ruling. This plan closes the config-file half: every value HQPTuner writes into `hqplayerd.xml` is escaped and read back unescaped (F-006), a staged value the daemon's own pages do not offer is refused before anything is written (F-006, F-013), staged values are bounded (F-018, F-019), the quadratic patterns are anchored (F-019), and a 401 after a normal answer stops blaming the credentials (F-013).

## Must be true when done

- A staged title of `a"b<c>d&e'f` lands in `hqplayerd.xml` as `a&quot;b&lt;c&gt;d&amp;e&apos;f`, and a config whose title carries those entities reads back as the original characters; `x"/><foo bar="baz` adds no element (AC1, D-08).
- `POST /api/config/stage` with `matrix_enabled` = `on`, or any value not among its page's choices, is refused and nothing is staged or written; the same value at `POST /api/config/live` is refused and nothing is held or sent (AC2, D-01).
- A staged value over the length ceiling, or a buffer pushed past the key ceiling, is refused at stage; an over-long value is refused at `POST /api/config/live` (AC4, D-09).
- A 401 that follows a normal answer earlier in the same apply answers an engine fault, not the refused-credentials sentence, and `credentials_ok` keeps its value (AC2, D-02).
- The five whitespace-leading patterns start on a literal and remove exactly the bytes they removed before (D-09).
