## Durable decisions

- D-01 (Lock): one hash-pinned lock produced with uv governs `check.yml` and every release build job, and resolves the darwin/win32-only `pystray` and `pillow` markers for all six build targets (AlmaLinux 8 amd64/arm64, macOS arm64/x86_64, Windows x64/arm64); `check.yml` moves off `pip install -e ".[dev]"` to it. Rejected: per-platform `pip-compile --generate-hashes` files. Evidence: `.github/workflows/release.yml:49-51,223-228,326-333`, `.github/workflows/check.yml:36-41,84-89`, `pyproject.toml:6-16`.
- D-02 (Python version): the image, CI and the release builds all run Python 3.14; the image moves from `python:3.12-slim` to a digest-pinned 3.14 slim base. Owner choice: "All on 3.14". Rejected: a 3.12 CI leg with its own lock, and one lock per interpreter. Evidence: `Dockerfile:1`, `.github/workflows/check.yml:23-27`, `.github/workflows/release.yml:50,227,312-315`, `pyproject.toml:5,259`.
- D-03 (macOS split): `build-macos` freezes with no secrets and uploads the unsigned `.app`; a new job in `environment: signing` downloads it, signs, builds the dmg, notarizes and staples, running no PyInstaller and no venv Python; `smoke-macos` and `publish` depend on the new job. Signing moves out of PyInstaller (`codesign_identity`, `entitlements_file`) and `package-macos.sh` drops its `.venv/bin/python` JSON parse on the signing path. Rejected: one job with a hashed install and the venv moved out of reach (PyInstaller still runs under the unlocked keychain). Evidence: `hqptuner.spec:24-28,73-74`, `scripts/package-macos.sh:25,51-52,84-104`, `.github/workflows/release.yml:207-301,305-381`.
- D-04 (Signing environment): the `signing` environment admits `dev` and `v*` tags only; both signing jobs name it and wait on `make check` on dev pushes as well as tags, either by dropping `tag-check`'s tag-only `if` or by a dev-push call to `check.yml`, accepting that `check` runs twice on some dev pushes. Owner choice: "dev and v* tags". Rejected: reviewed dispatch on other branches, and tags only (dev smoke rows would run unsigned). Evidence: `.github/workflows/release.yml:3-15,21-25,301,346-347,386-403`, `.github/workflows/check.yml:4-8`, commit `7097145f`.
- D-05 (Settings halves): moving the `MACOS_*` and `NOTARY_*` secrets into `signing` and setting its branch rule are owner actions in GitHub settings, outside the tree; the repo half is proved by the gate and the settings half is recorded as a Note in the finding's entry naming the owner's action. Evidence: `.github/workflows/release.yml:207-260,350`, `.planning/security/REPORT.md:1655`.
- D-06 (F-042 triviajudge): triviajudge is not pinned, and stays outside the hashed lock. Owner decision, quoted: "it's my app I update it when I fucking want". Rejected: a git-commit pin, and a PyPI version-and-hash pin. Evidence: `pyproject.toml:31-34`, `/home/atom/dev/triviajudge/pyproject.toml:2-3`.
- D-07 (Action pins): every remote `uses:` (36 refs, 11 actions across `release.yml`, `docker.yml`, `check.yml`) is pinned to a full 40-hex commit SHA with the tag as a trailing comment; the 2 local `./.github/workflows/check.yml` calls stay; a `.github/dependabot.yml` covers `github-actions` and `pip`. Rejected: Renovate, and SHA pins bumped by hand. Evidence: `.github/workflows/release.yml`, `.github/workflows/docker.yml:25,38-44,62`, `.github/workflows/check.yml`.
- D-08 (Dev host): the lock binds CI and the release builds only; the dev venv keeps its editable filepawl and triviajudge installs. Rejected: holding the dev venv to the lock. Evidence: `.venv/lib64/python3.14/site-packages/filepawl-*.dist-info/direct_url.json`, `.venv/lib64/python3.14/site-packages/triviajudge-0.3.0.dist-info/direct_url.json`.

## Decisions

- D-10 (Proof vehicle): tree-side fixes are proved by a new offline gate under `scripts/gates/` that reads the workflows, `hqptuner.spec`, `Dockerfile`, `pyproject.toml` and `simplysign-login.ps1`; its tests sit in `tests/gates/` and drive its seams on literal source strings; it is wired into the Makefile `lint` target and `.pre-commit-config.yaml`; its red run is the gate against the pre-fix files. If it parses YAML, `pyyaml` and `types-PyYAML` are added to the dev extras. Evidence: `scripts/gates/check_container_env.py:1-40`, `tests/gates/test_container_env.py:1-40`, `scripts/gates/check_gates_wired.py:17-37`, `.pre-commit-config.yaml:306-309`, `pyproject.toml:19-54,258-264`, `docs/testing.md` rule 8.
