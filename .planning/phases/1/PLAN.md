# Phase 1: Snapshots stay on their stations - Plan 1: Save never removes a snapshot from an unticked station

## Goal

A user saving a snapshot to one station keeps every snapshot on every other station.

## Must be true when done

- In the Snapshot builder, opening a saved snapshot on station A, unticking A, ticking B and pressing Save leaves that snapshot on A as it was, and puts the saved one on B.
- The same holds when the save also renames the snapshot: with A unticked, A keeps the snapshot under its old name and B gets the new name.
- After any snapshot save, every snapshot a station that was not ticked held before the save is still on that station.
- The saved snapshot is on every station that was ticked for the save.
- Renaming a snapshot on its own station, with that station still ticked, still replaces the old name on that station (unchanged behavior).
- The builders' save model states the same no-move rule as the shell: `savedTo` has no move branch and no `keep` option.

## Context

- Cause, read in code: `write` in `hqptuner/static/store/faceplate/builders/shell.js` sends `api.deleteLivePreset(from.name, from.st)` whenever the edited record's own station is not among the ticked stations (`gone` is true when `!to.includes(from.st)`). That DELETE is the erasure. The rule it mirrors is `savedTo`'s "one whose own station is unticked moves out of it, unless `keep` holds it there" in `hqptuner/static/model/builders/builder.js`.
- The backend is already correct and already pinned: `LivePresetStore.save` in `hqptuner/presets/store/live.py` writes only the stations it is given, and `tests/presets/stores/test_live_preset_stations.py` pins one station's save and delete leaving the others. No Python change is planned.
- Spec: `docs/spec/faceplate.md` "Snapshot builder" says only "Save writes to every ticked station"; no spec line asks for a move, so no doc change is needed.
- No CONTEXT.md exists for this phase. No user-facing text changes (the Snapshot builder's copy has no "move" wording). No CHANGELOG entry (owner's alone until handed back).
- Out of scope: the Profile builder's rename path (`write` in `profile-save.js` staging a delete of the old name from the stations holding it); it is a matrix-profile rename, not a snapshot save, and already passes `keep: true` to `savedTo`.
