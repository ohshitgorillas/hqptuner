## Durable decisions

- D-01 (Login host): a login may name any host; the typed username and password are checked at that host, and an accepted login to a different host replaces the stored record with that host and pair, so the old pair is never sent to the new host. Rejected: refusing a login that names a new host, which would block a legitimate first login. Today's login already does this: it checks only the typed pair, never the stored one. Accepted by the owner, for the F-004 and F-005 dispositions: a caller who can reach the app before login can still retarget it to a server they control, so the owner re-enters the real host and pair, and can still learn through the login whether another host answers; no stored credential leaves either way. Evidence: `hqptuner/api/login.py:100-113`, `hqptuner/conf/httpauth.py:133-169`, `hqptuner/static/store/setup.js:292-296`, `tests/js/store/setup.test.js:351`.
- D-02 (Host change): a Connection save that changes the host is refused unless the request carries both the username and the password; a save to the same host with a blank password keeps the stored one. The refusal text is owner copy, verbatim: "HQPTuner requires a new username and password when switching host addresses for security; please re-enter your credentials." Rejected: requiring the password only when it is non-stock, and moving host changes onto the login route. The login cookie carries only a fingerprint of the pair in force, so there is no per-browser pair to reuse. Evidence: `hqptuner/api/routes/connection.py:146-160`, `hqptuner/core/login.py` (`_fingerprint`, `mint`).
- D-03 (Validator): one host validator in `hqptuner/conf/` accepts a DNS hostname, an IPv4 literal or an IPv6 literal, and refuses a port, path, query, userinfo, whitespace, a zone ID or an empty value; it runs at the Connection save, at login and when the saved record is read at startup. IPv6 is stored bare (`::1`), bracketed wherever an 8088 URL is built, and kept bare for the 4321 socket. Rejected: refusing IPv6 in v1, and a validator in `api` that startup in `core` cannot import. Evidence: httpx 0.28.1 probe of 2026-11-08 (`target:9000/path?x=` builds with no error, `a:b` and `::1` raise `InvalidURL`), `pyproject.toml` `[tool.importlinter]`, `hqptuner/conf/httpconf.py:164-169`, `hqptuner/engine/logtail.py:50-52`, `hqptuner/config.py:245-247`, `hqptuner/static/components/Setup.js:115`, `hqptuner/core/loader.py:41-47`.
- D-04 (Container alias): `host.docker.internal` is probed only when a marker the image sets in its `Dockerfile` `ENV` block is present, both at startup and in the `/api/discover` empty-sweep fallback; when found it is offered as a choice and never written into `cfg.hqp_host` on its own. Docker only; podman is not a v1 concern. Rejected: sniffing `/.dockerenv` or `/run/.containerenv`, and scoping the gate to startup alone. Evidence: `Dockerfile:16-25`, `hqptuner/config.py:144-148`, `hqptuner/api/lifespan.py:27-54`, `hqptuner/engine/discovery.py:246-274`, `compose.yaml:23-24`.

## Decisions

- D-05 (Gate coverage): phase 4's gate already covers `POST /api/connection` and `GET /api/discover`, so a stranger can no longer name a host there; what this phase closes is a logged-in browser steered into a host-only save, the open login route (D-01), and `remember:true` writing a pinned or in-memory password. Evidence: `hqptuner/api/gate.py:25`, `hqptuner/api/routes/connection.py:146-154`.
- D-06 (Pinned values): the Connection save follows the login's pin rule (`LoginValuesPinnedError`), and a value the environment pins is never copied into `connection.json`. Evidence: `hqptuner/api/routes/connection.py:146-153`, `hqptuner/core/connection.py:101-118,152-157`, `hqptuner/api/login.py:63-74,101-102`.
- D-07 (Discovered daemons): the Connection panel lists discovered daemons for the user to choose; a single answering daemon no longer fills the host field silently. Evidence: `hqptuner/static/store/setup.js:240-253,341-346`.
- D-08 (Save while down): a Connection save still works when the daemon does not answer; no daemon check is added before the save. Evidence: `hqptuner/api/routes/connection.py:136-141`, `CLAUDE.md` ("User actions always proceed").
- D-09 (Startup recovery): a saved record whose host fails D-03 is handled like a corrupt record: a logged warning, and the app starts without that host so the Connection panel opens; the file stays until the user saves over it. A corrupt or invalid record counts as a chosen host, so it does not start the alias probe. Both `create_app` and `_adopt_alias` are covered. Evidence: `hqptuner/api/factory.py:58-68`, `hqptuner/api/lifespan.py:36-54`, `hqptuner/core/connection.py:135-141,160-169`, `hqptuner/__main__.py:37-45`.
- D-10 (Refusal sentences): the three 8088 refusal sentences stay; after D-03, the fixed port and the login gate, they tell only a logged-in caller whether 8088 is open on a host. Evidence: `hqptuner/conf/httpconf.py:130-150`, `hqptuner/conf/noanswer.py:13-35`.
- D-11 (Retired clients): a replaced 8088 client is closed once the requests holding it finish, and the shutdown-only `_retired` list goes; an in-flight restore or apply is not aborted. Evidence: `hqptuner/core/manager.py:88-89,161-171,266-278`, `hqptuner/api/lifespan.py:123-127`.
- D-12 (8088 bounds): every 8088 read carries a size ceiling set per path and a total deadline: the three forms, `/config/refresh`, `/backup/settings.zip`, `logtail.fetch_log`, `release.fetch_about` and `check_pair`. Settings backups measured 4.7 to 8.7 MB (n=26) and forms 4.6 to 29.5 KB, so one ceiling does not fit. Evidence: `hqptuner/conf/httpconf.py:192-201,220-243,308-314`, `hqptuner/engine/logtail.py:17,43-66`, `hqptuner/engine/release.py:20-30`, `hqptuner/conf/httpauth.py:153-161`, `hqptuner/core/loader.py:61-64,184`.
- D-13 (Deadline clock): the total deadline runs on the injectable clock or `Deadline` the control lane uses, not httpx's per-read timeout and not a wall clock, so it reaches `HttpOptions` and `Network.http_options`. Evidence: `hqptuner/conf/httpconf.py:120-127`, `hqptuner/core/network.py`, `hqptuner/engine/control.py:47-52`, `docs/testing.md`.
- D-14 (Control API drip): in scope: a total deadline per Control API document and a scan that does not re-decode the whole buffer per chunk; the 4 MiB `MAX_RESPONSE` cap stays. Evidence: `hqptuner/engine/control.py:36,199-216`.
- D-15 (Discovery): `parse_reply` uses `defusedxml.ElementTree.fromstring` and drops its `noqa: S314`; `_collect` caps the reply count and the bytes kept and yields on every pass; the cap also bounds the sequential 4321 dials. Evidence: `hqptuner/engine/discovery.py:103-115,197-217,276-279`, `hqptuner/engine/frames.py:11-12`.
- D-16 (File mode): `ConnectionStore.write` creates its file with mode 0600 through `os.open`, the pattern `LoginSecret.persist` uses, and a leftover temp file with a wider mode does not carry that mode into the result. Evidence: `hqptuner/core/login.py:74-92`, `hqptuner/core/connection.py:101-118`.
- D-17 (Copy): every other visible text change ships only in owner-approved wording: the discovered-daemon list and its prompt, the blank-password placeholder ("Leave blank to keep the stored password"), the invalid-host refusal, the note that the stored password is unencrypted, the alias offer, and the `CHANGELOG.md` `[Unreleased]` `### Security` entry. Evidence: `hqptuner/static/components/Setup.js:78-90,102-110,204-213`, `CLAUDE.md` copy rule, phase 4 D-15.
- D-18 (Tests): the tests pinning the auto-fill (`tests/js/store/setup.test.js:167`) and the startup alias adoption (`tests/api/test_container_host_alias.py:93`) are replaced as owner-approved behavior changes, not edited to pass; new Python tests go in directories under the 30-file cap (`tests/api/login/`, `tests/api/surface/`, `tests/engine/http/`), not in `tests/api` or `tests/engine`.
- D-19 (Record): each finding's disposition goes in `.planning/security/DISPOSITIONS.md` in the phase 4 shape: disposition, commits, proof test.

## Acceptance criteria

- [ ] AC1: a login naming a host other than the one in force sends that host only the typed username and password, never the stored pair, and when accepted replaces the saved record with that host and pair; a Connection save that changes the host without both a username and a password answers "HQPTuner requires a new username and password when switching host addresses for security; please re-enter your credentials.", saves nothing and sends no request to the new host
- [ ] AC2: a host of `a:b`, `target:9000/path?x=` or `fe80::1%eth0` is refused at the Connection save and at login with nothing saved; a host of `::1` is accepted and the 8088 lane requests `http://[::1]:8088/...`
- [ ] AC3: with `connection.json` holding the host `a:b` at start, the app starts, `/api/health` answers 200, and the SPA shows the Connection panel
- [ ] AC4: without the image marker, a start with no saved host and an empty `/api/discover` sweep send no request to `host.docker.internal`; with the marker, a start does not set the host from the alias
- [ ] AC5: an 8088 response larger than its path's ceiling is refused; an 8088 or 4321 response still dripping past its total deadline on the test clock is abandoned; after a Connection save the replaced 8088 client is closed once its in-flight requests finish
- [ ] AC6: a discovery reply carrying an XML entity declaration is rejected, and one sweep keeps and dials at most the reply cap however many senders answer
- [ ] AC7: `.planning/security/DISPOSITIONS.md` lists all 8 findings, each naming its fixing commit and a proof test that fails against the pre-fix code, and `check`, `e2e`, `smoke`, `lifecycle-deb`, `lifecycle-rpm`, `smoke-macos` and `smoke-windows` pass on the phase's last `dev` commit (ci: check, e2e, smoke, lifecycle-deb, lifecycle-rpm, smoke-macos, smoke-windows)

## Flagged assumptions

- Whether httpx 0.28 `client.stream()` with `aiter_bytes()` and `DigestAuth` replays the 401 challenge without buffering the first body, and whether `Response.num_bytes_downloaded` can enforce a ceiling before decompression - Unclear (research); if wrong: D-12's ceiling has to sit somewhere other than the stream read.
- What mode 0600 means on Windows (only the read-only bit) and the default ACL of the frozen build's per-user data directory - Unclear (research); if wrong: the F-023 disposition and the "stored unencrypted" note overstate the protection on Windows.
- The image marker is enough for container detection because only Docker is supported - Confident by owner ruling; if wrong: a podman user loses the alias offer.
- Each fixing plan needs its owner-approved copy from D-17 before implementation - Confident; if wrong: the plan stalls at a copy task it never asked for.
